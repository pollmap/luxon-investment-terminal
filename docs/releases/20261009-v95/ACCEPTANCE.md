## 구현한 변경

### 조회와 저장

1. 38.9MB 종목 목록이 32MiB 일반 캐시에 들어가지 않아 반복 해석되던 경로를 수정했습니다. 같은 내부 버전의 종목 목록과 행 색인을 공유하며 이전 버전 전체를 계속 보관하지 않습니다.
2. DB 연결을 잡은 채 캐시 잠금을 기다리는 경로를 제거했습니다. 반대 순서로 잠금을 잡는 호출과 동시 실행하면 연결 풀이 고갈될 수 있었습니다.
3. 개별 상세는 전체 종목 자료를 합성하지 않고 해당 종목만 사용합니다. 다른 종목의 가격 변화로 응답 캐시가 불필요하게 무효화되지 않게 했습니다.
4. 상세 응답 뒤에 갱신 작업을 기록하며 중복 기록을 합칩니다. 기간별 가격 조회는 필요한 구간만 읽고 전체 확보 범위는 별도 메타데이터로 유지합니다.
5. 실제 저장값이 같은 시각에 연속 변경되어도 내부 revision이 원자적으로 증가합니다. 원천 기준일·수신 시각은 바꾸지 않으며 동일 값 재저장은 revision을 유지합니다.
6. 재수집 시각만 달라진 동일 재무 사실의 중복 생성을 막습니다. 기존 ID와 참조는 보존합니다. 신규 시계열 JSON에서 불필요한 직렬화 공백을 줄였습니다. 기존 DB 파일 전체를 압축하거나 중복 삭제한 것은 아닙니다.

### 화면과 수집

- 상세를 보는 동안 숨겨진 시장 목록의 구독·폴링을 중단하고 복귀 시 목록 상태를 유지합니다.
- 검색창과 단축키 검색은 종목 식별 색인을 공유합니다. 입력할 때마다 실시간 검색 API를 호출하지 않습니다.
- 닫힌 지수 상세·숨겨진 화면의 요청을 줄였고 차트 라이브러리를 필요한 화면에서 불러옵니다.
- 다른 지표·회계 기준으로 바꾼 조회가 실패하면 이전 분석값을 새 선택의 값처럼 표시하지 않습니다. 조회 실패를 ‘실적이 없음’으로 단정하지 않고 재시도를 제공합니다.
- 주식 수 검토 결과가 자동 작업자에 전달되도록 연결했습니다. 회사·종목·접수번호·공식 문서 주소·실제 원본 해시가 맞는 명시적 검토만 사용합니다. 같은 날 같은 검토 상태의 반복 호출을 줄이고 근거가 바뀌면 저장한 구간을 재평가합니다.
- 주식분할 사건의 미검토 차단은 유지합니다. 이 변경으로 새 기업의 주식단위 검증을 자동 승인하지 않았습니다.

PC 공용 인터넷에서 HTTP/2 TLS 연결 하나에 동시 스트림 100개, 검색어 10개·종목 10개를 사용했습니다. 첫 100회, 캐시 사용 구간 300회, 1.6초 후 100회를 각각 측정했습니다. 이는 서로 다른 사용자 100명의 독립 연결 시험과 동일하지 않습니다. 수집기는 계속 동작했습니다. 캐시·자료가 완전히 고정된 실험은 아닙니다.

## 정리와 용량

- 정지한 로컬 복원 시험 DB와 실패한 전송 임시 파일을 경로·사용 상태·원본 백업 보존 여부 확인 후 정리했습니다. C 드라이브 여유는 관측상 40.83GB에서 78.18GB로 늘었습니다. 차이는 37.35GB이며 동시에 수행한 빌드의 영향이 포함될 수 있습니다.
- VPS 비활성 배포본 6개는 PC 압축 사본의 SHA와 전체 멤버를 확인하고 배포본 하나를 실제 복원한 후 삭제했습니다. 대상의 논리적 파일 크기는 0.91GB입니다. 이를 실제 디스크 회수량으로 단정하지 않습니다.
- 최신 관측 용량은 77.32%, 여유 약 35.1GB였습니다. 수집 큐는 `ready`이나 수집 완료를 의미하지 않습니다.
- DB·원본·정정·사용자 설정·다른 VPS 프로젝트는 삭제하지 않았습니다. 자동 승인 검토가 차단한 별도 실패 복원 시험 폴더도 보존했습니다.
