# v27 과거 공시 수집 연결 — 2026-10-04

공개 배포: 20261004-history-v27. API·수집기·웹·OpenAlgo 실행과 이전 주소 보존 확인.

## 공개 반영
- 공시 목록의 사업/반기보고서를 XBRL 수집 대기열에 연결한다. 정정 본문을 포함하고 첨부정정은 제외한다.
- 비12월 결산 회사의 분기보고서 코드를 월만 보고 추측하지 않는다. 미확정 접수번호는 별도 대기 상태에 둔다.
- 이미 확보한 과거 목록도 새 API 호출 없이 대기열로 옮긴다. 기존 완료 작업과 원본은 보존한다.
- 현재 화면에 없는 회사에도 공시 목록 수집 순서를 배정한다. 전체 종목 전용 커서를 따로 두어 5개 간격으로 같은 일부 회사만 반복하는 현상을 방지한다.
- 공개 서버에서 삼성전자·SK하이닉스·현대차의 과거 XBRL 대기열을 확인했다. 현대차에는 대기열 11건을 추가했다. 전체 과거 자료 확보 완료는 아니다.

## 로컬 구현·검증, 아직 공개 미반영
- split_units.py: 명시적으로 검증된 분할 이력과 공시별 주식 단위로만 가격·주식 수·EPS를 같은 기준으로 변환한다.
- 이미 소급 수정된 비교 공시를 두 번 나누지 않는다. 원본 사실은 보존하고 변환 결과에 별도 식별자·산식·원본 ID를 연결한다.
- 역분할, 금액 총액 불변, 원주가 보존, 거래대금 불변, 반올림 오차 변환, 미확인 공시 및 우선주 차단을 테스트했다.
- SQLite 시계열에서 읽은 가격 행에 실제 변환을 적용하도록 분석 입력 경로를 수정했다. 메타데이터만 수정하고 숫자는 그대로 두지 않는다.
- 관련 테스트 20개 통과. 실제 분할을 가로지르는 공개 비교선 완료로 판정하지 않는다.

## 발견한 추가 원인
- 삼성전자 구형 XBRL에서 EPS 단위가 shares로 기록된 사례가 있다. 이 값을 주식 수로 간주해 분할 비율을 곱하지 않도록 차단했다.
- 구형 IFRS taxonomy와 주석 계정, 원문 단위를 확인해 단위 보완 근거를 연결해야 한다. 검증 전 전역 단위 치환은 하지 않는다.

## 다음 작업
1. 구형 EPS·가중평균 주식 수·귀속이익 원문과 taxonomy를 대조하고 공시별 단위 검증을 연결한다.
2. 실제 삼성전자 2018년 분할 원문과 분할 전후 공시를 결합해 차트·TTM·표를 대조한다.
3. 배당의 실제 지급일·배당락일·기업행사 범위를 수집해 재투자 계산을 연결한다.
