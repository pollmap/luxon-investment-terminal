초기 Linux CI는 암호화 라이브러리 선언 누락, 검사가 임시 작업 폴더의 코드를 가져오는 문제, 네트워크 격리 환경의 오프라인 상태 때문에 실패했습니다. 필요한 도구를 정식 경로로 이동하고 의존성을 선언했습니다. 오프라인 시험은 앱의 보호 로직을 제거하지 않고 `offline → 구독 해제 → online → 단일 재구독`을 검증합니다.

실제 운영 API에는 이미 AnyIO 4.15.1·SoupSieve 2.10이 설치돼 있었습니다. 이번에는 저장소의 설치 기준과 잠금 파일도 맞췄습니다. cryptography는 기존 로컬 암호화 도구와 동일한 50.0.2를 사용하고 숨은 임시 라이브러리 경로 의존을 제거했습니다.

남은 npm 경고는 lint 도구 경로의 `braces` 깊은 패턴 처리 문제이며 공개 웹 실행 의존성이 아닙니다. 확인 시 수정 버전이 없어 임의로 경고를 무시하거나 라이브러리를 바꾸지 않았습니다. [해당 경고](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)

## GitHub 보안 검토 상태

누적 소스를 게시하면서 CodeQL이 새 경고 327개를 보고했습니다(critical 16, high 310, medium 1). 경고 개수와 서로 독립된 취약점 개수는 다릅니다. 분석 작업은 실행됐지만 **CodeQL 보안 판정은 통과하지 않았습니다**. 기능 CI 통과와 구분합니다.

최고 등급 16개의 입력 경로를 확인한 결과, 배포·복원 CLI, 운영자가 선택한 벤치마크 URL, 내부 서비스 URL 환경변수, 고정 Toss URL의 수집 경로가 포함됐습니다. 이번 제한 검토에서 공개 HTTP 사용자가 임의 호스트나 명령을 정하는 경로는 발견하지 못했습니다. 나머지 경로 경고 306개를 개별 전수 승인한 상태는 아니므로 일괄 무시하지 않습니다. PR은 이 검토가 남아 있어 기본 브랜치에 병합하지 않았습니다.
