## 보관 도구의 재발 방지

`scripts/offsite_release_archive.py`에 로컬 여유 공간 보호를 추가했습니다.

- 기본 최소 여유는 1GiB이며 `--min-free-gib`로 더 크게 설정할 수 있습니다.
- 다운로드 시작 전과 각 1MiB 쓰기 전에 검사합니다. 복원은 전체 예상 크기도 먼저 검사합니다.
- 공간 부족이나 쓰기 실패 시 해당 다운로드 자식만 중단합니다. 기존 보관본·부분 파일·복원 자료를 지우지 않습니다.
- 경로 제한·전체 내용 해시·복원 검증·기존 `--resume`은 유지합니다. 파일 해시 계산은 전체 파일을 메모리에 올리지 않습니다.

관련 로컬 회귀 48개와 Ruff·diff 검사가 통과했습니다. 중간 공간 부족·자식 종료·기존 파일 보존·복원 불일치를 포함합니다. 위 실제 원격 보관은 수정 전 도구로 수행했고, 새 보호 로직의 네트워크 장애 실험으로 과장하지 않습니다. 이 도구는 로컬 운영 CLI여서 공개 앱 재배포가 필요하지 않습니다.

- 압축 전 실제 파일 할당: 6,442,450,944바이트.
- 압축 후 실제 파일 할당: 3,078,565,888바이트.
- 차이: **3,363,885,056바이트**. 전체 드라이브 여유 변화와 구분합니다.
- 6개 모두 전체 SHA-256·논리 길이가 전후 동일하고 독립 복원 증거 파일도 불변입니다.
- 06:51:43~46 로컬 PG17 재기동·읽기·정상 종료를 확인했습니다. 체크포인트는 15,792,000행, 남은 복사는 1,103,854행으로 같습니다.

이후 원본과 후보 전체 대조를 재개했습니다. 최대 90분·최소 여유 6GiB를 유지하며, 이미 커밋한 행을 원본과 비교한 다음 누락된 행만 이어 씁니다. 마지막에는 독립적인 전행 checksum을 검사합니다. **현재 문서 시점에는 이 검증이 진행 중입니다.** NTFS 압축으로 줄어든 공간을 PostgreSQL 저장 구조 개선 효과에 합산하지 않습니다. 운영 DB를 후보로 교체하지 않았습니다.
