# 시장 수급 주·월·년 과거 페이지 재개

2026-10-09. v91 API 감사에서 확인한 누락을 수정한 v92 후보 기록이다. 구현과 로컬 검증을 기록하며 실제 공급자 전 기간 확보·v92 공개 배포는 별도 확인한다.

## 문제와 변경

시장 수급 화면은 코스피·코스닥의 일·주·월·년을 선택할 수 있었지만, 예약 수집은 일별 자료만 이전 페이지로 이동했다. 주·월·년의 첫 조회에 다음 커서가 있어도 100개 뒤의 자료가 늘어나지 않았다.

`TossMarket.pending_history_jobs`가 실제 저장된 화면 요청에서 주·월·년 조합을 읽는다. 요청하지 않은 조합은 생성하지 않는다. 유효한 과거 커서가 있고 원천 끝에 도달하지 않은 시리즈만 기존 지수·일별 시장 수급과 함께 순환한다. 한 예약 순환당 이전 페이지 1개, 동일 토스 클라이언트·인증·호출 예산을 유지한다. 화면을 닫거나 작업자를 재시작해도 저장된 요청 의도로 과거 수집을 이어갈 수 있다.

최신 페이지 갱신과 과거 페이지 수집은 작업 키가 다르다. 같은 시리즈를 동시에 읽고 저장하면서 한쪽 페이지가 사라지는 것을 막기 위해 시리즈별 잠금을 추가했다. 최신 페이지를 받은 시각과 과거 페이지를 받은 시각도 구분한다.

## 응답별 처리

| 응답 | 저장·커서 처리 |
|---|---|
| 정상 행과 더 오래된 `nextUntil` | 행을 병합하고, 과거 조회일 때만 이전 커서를 진행 |
| 과거 조회의 명시적 `nextUntil:null` | 기존 행 보존, `backfill_complete=true`, `history_status=exhausted` |
| 과거 조회의 정상 빈 행·명시적 null | 조회 범위의 끝으로 확인하되 기존 행을 지우지 않음 |
| 기존 자료가 있는데 최신 페이지만 빈 배열 | 값·커서를 유지하고 `stale`, 전체 과거 완료로 승격하지 않음 |
| 최초 정상 빈 배열·명시적 null | `no_data`. 나중에 최신 자료가 생기면 정상 수집을 다시 시작 가능 |
| 선택 필드 `nextUntil` 자체가 없음 | 명시적 null과 구분. `cursor_unconfirmed`, 기존 커서·미완료 상태 유지 |
| 잘못된 날짜·중복 날짜·앞으로 진행하는 커서·요청 범위 밖 행·빈 배열＋다음 커서 | 오류 기록, 마지막 정상 행·커서 유지 |
| HTTP·인증·시간 초과 | 기존 `run_job` 오류·재시도 정책 적용, 정상 자료 보존 |

공식 현재 스키마에서 `nextUntil`은 선택 필드이고, 값이 null이면 더 이상 자료가 없음을 뜻한다. 필드 생략을 원천 끝으로 해석하지 않는다. 기준일은 inclusive이므로 다음 페이지 커서와 실제 행 날짜를 함께 검사한다. [공식 REST 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)

## 검증

`tests/test_market_investor_history.py`의 합성 자료 회귀 11개를 추가했다.

- 실제 요청한 주·월·년만 선택하고 요청하지 않은 다른 시장 조합은 제외.
- 세 번의 예약 순환에서 세 조합을 각 한 페이지씩 처리. 기존 호출 수 상한 유지.
- 최신 갱신이 깊은 과거 커서를 덮어쓰지 않고 명시적 마지막 페이지에서 종료.
- 최신 빈 응답과 정상 과거 종료의 차이, 최초 자료 없음 이후 신규 자료 수집.
- 오류·형식 이상에도 행·커서 유지, 선택 커서 생략을 완료로 오판하지 않음.
- 최신 갱신과 과거 수집을 동시에 시작해 두 페이지가 모두 보존됨.

기존 요청 스케줄러·섹터 복구·토스 시장 검사를 포함해 **29개 통과**, Ruff F와 Python 컴파일 검사 통과. 공급자 호출을 추가로 실행하지 않았으므로 실제 주·월·년 이력의 확대와 종료는 배포 후 저장된 커서·행 수로 확인한다.

관련 파일: `services/market_dashboard/toss_market.py`, `tests/test_market_investor_history.py`. StockWarnings의 오류·stale 및 시장 수급 `no_data` 화면은 프런트 담당 작업에 계약을 전달했다.

## v92 공개 요청 → 실제 작업자 반영
