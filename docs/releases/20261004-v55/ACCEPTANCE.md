# v55 — 신규 상장과 누락된 자료 작업의 자동 등록

공개 버전 `20261004-listing-queue-v55`. 기존 가격·원본·재무·수집 커서·사용자 설정을 보존했다.

## 실제 문제와 변경

직전 전체 목록과 큐의 차이를 서버에서 대조했다. 전체 2,875종목 중 브릴스(468670)의 조정 일봉·투자자·프로그램·공매도·신용·대차 작업이 누락돼 있었다. 원주가 일봉은 이미 2026-10-01~02의 2행을 수집한 상태였다. 삼성전자우(005935) 프로그램 작업도 없었으나 원천 스냅샷은 이미 자료 없음 상태였다.

작업자는 시작 및 종목 목록 변경 시 현재 종목×7종 자료를 대조해 없는 작업만 queued로 등록한다. 기존 성공·실패 상태와 원본 및 과거 수집 커서는 덮어쓰지 않는다. 등록은 수집 완료가 아니다.

한 번 이상 전체 순회한 뒤, 기존 5회 중 1회 우선 처리 차례에 화면 요청이 없으면 queued 작업을 처리한다. 화면 요청이 우선이며 나머지 차례에는 전체 수집이 진행된다. 기존 호출 한도·인증·예외 처리와 페이지 제한은 유지한다.

숫자 인덱스와 함께 다음 종목코드를 저장한다. 신규 상장으로 정렬된 목록 중간에 종목이 들어가도 처리 예정 종목이 바뀌지 않는다. 예정 종목이 없어지면 다음 코드로 진행한다. 기존 숫자 커서는 최초 전환 때 그대로 사용한다.

이미 최신·전체 원천 범위가 확인된 스냅샷이 있다면, supplier 재요청 없이 해당 작업을 ready/no_data로 반영한다. 오래된 자료나 남은 페이지를 전체 완료로 승격하지 않는다.

## 검증

- 큐·원천 미지원·기존 과거 자료 보존 테스트 44개 통과.
- 신규 상장 삽입, 예정 종목 제거, 재시작, 수집 순회와 우선 처리의 병행, 기존 오류와 커서 보존, 원천 재요청 없는 상태 반영 검사.
- 공개 health에서 v55 확인. 브릴스·삼성전자 실제 요약 경로 `securities/{code}?view=summary` HTTP 200.
- 첫 smoke에 사용한 `/summary` 경로는 기존 API에 없는 경로라 404였다. 올바른 기존 경로로 다시 검사했으며 이를 종목 자료 미지원으로 분류하지 않았다.
- 실제 서버 대조에서 2,875종목×7종류 모두 등록되어 missing 작업은 0개. 이것은 작업 등록 범위이며 데이터 확보율이 아니다.
- 삼성전자우 프로그램은 기존 no_data 응답을 반영했다. 브릴스 신용은 새 조회 후 no_data, 원주가 2행은 보존됐다. 나머지 브릴스 자료는 후속 수집 대기로 확인됐다.
- 작업 시도는 49,791→49,797로 진행했고 다음 종목 식별 커서와 우선 처리 횟수가 기록됐다. 대기 상태 파일만으로 실행 중이라고 주장하지 않았다.

근거: `work/remaining-v55/queue-before.json`, `queue-after.json`, `queue-followup.json`, `queue-latest.json`, `public.json`, `public-correct-routes.json`, `tests.xml`.

변경 파일: `services/market_dashboard/toss_backfill.py`, `tests/test_toss_backfill.py`, `DECISIONS.md`.

전체 과거 자료 및 404 보완, 전 기업 TTM·주식분할 검증, 배당 기업행사·재투자, 실제 장중 수신과 복구, 공개 성능 목표, 실사용 검증은 여전히 남아 있다. 이번 작업은 신규 종목의 빠진 수집 경로를 보완한 것이며 전체 서비스 완료로 처리하지 않는다.
