# v41 — 우선주 회사 공시·프로필 연결

공개 실행 버전 `20261004-issuer-documents-v41`을 health에서 확인했다. 프런트엔드와 공개 주소는 유지했다. 기존 수집·DB·사용자 저장값과 다른 VPS 서비스는 변경하지 않았다.

## 실제 문제와 수정

운영 DB에서 현대차(005380)의 회사 공시 목록은 100건·ready이고 프로필이 있었지만, 현대차우(005385), 현대차2우B(005387), 현대차3우B(005389)는 공시 0건·unavailable, 회사 프로필 없음이었다. DART corpCode 목록은 보통주 종목코드를 사용한다. 우선주의 코드가 매핑되지 않았다는 사실을 회사 공시 자체의 미제공으로 취급하고 있었다.

`issuer_documents.py`를 추가해 앞서 공식 Hyundai IR 종목 탭에서 검토한 4종목에만 회사 문서 연결을 적용했다. 현재 universe의 보통주·요청 우선주 이름이 정확히 일치하고, 보통주 DART 회사 식별자가 있어야 연결한다. 코드 접미사·유사 이름으로 다른 우선주를 자동 연결하지 않는다. 우선주 자체의 DART 매핑이 있으면 그 매핑을 우선한다.

수집기의 `filings()` 경로에서 보통주의 기존 회사 프로필·공시 목록을 재사용한다. 원문 receipt·URL·출처는 그대로 유지하고 회사 문서 공유를 나타내는 `issuer_link`를 추가한다. 15분 내 ready 공시라면 동일 회사의 API 요청을 반복하지 않는다. 오래됐거나 수집 미완료이면 기존 보통주 수집 경로로 갱신하고 다시 공유한다. 갱신 실패 시 공유해 둔 마지막 정상 문서는 남는다. DART 예산을 우회하지 않는다.

공유 범위는 회사 프로필과 공시 문서다. 가격, 배당 이벤트, financial statements, EPS·TTM·주식 수·회사 재무총액이나 report_facts는 복사하지 않는다. 기존 우선주 재무 사실과 출처를 보존하고 회사 프로필 출처는 `company_source_trace`로 별도 기록한다. 공식 조회 projection 버전은 8로 올렸고 Store의 쓰기와 읽기가 같은 상수를 사용한다.

## 검증

- 관련 테스트 61개 통과: 정확한 식별/매핑 우선순위, 회사 문서만 공유, 가격·배당 비공유, 마지막 정상 공시 보존, 새 API 요청 없이 3종목 재사용, 실패 후 복구 자료 유지, 공식 projection 및 상세 API 회귀.
- 운영 DB 실제 전후: 우선주 3종목 각각 0 → 100개 회사 공시, 회사 프로필 `현대자동차(주)` 연결.
- 동일 작업 직전·직후 events/prices/detail/toss:daily-chart 저장값의 해시가 동일했다. 다른 종목의 가격·주당 자료를 복사하지 않았다.
- 공개 `view=filings`, `view=company`에서 3종목의 실제 security code, 100개 목록과 회사 프로필을 확인했다. 공개 health의 실행 버전도 일치했다.

근거: `work/remaining-v41/before.json`, `live.json`, `public.json`, `tests.xml`, `live_probe.py`. 공식 매핑 원문은 v39에서 검토한 Hyundai IR Euroland 종목 탭이다. 원본 자료를 토스 출처로 바꾸지 않았다.

## 범위와 남은 작업

100건은 보통주에 현재 수집돼 있던 공시 목록의 공유 결과다. 전 기간 회사 공시의 수집 완료를 뜻하지 않는다. 다른 회사 우선주의 식별, 주당 재무·배당락일·기업행사·재투자는 완료되지 않았다. 시작 때 조사한 삼성 IR 페이지는 연간 배당 총액·주당액 표였고, 개별 배당 지급일/배당락일 근거로 사용하지 않았다. 연간 금액을 임의의 지급일 이벤트로 생성하지 않는다.

전체 과거 자료·404, TTM 및 분할 범위 확대, 실제 거래일 체결·호가·화면·복구 증거, 공개 100동시 요청 성능, 실제 사용자 과제도 남아 있다. 이번 버전은 성능 개선 버전으로 측정하지 않았다. 전체 완료로 처리하지 않는다.
