## 2. Cloudflare API 캐시와 공개 성능

실제 API 응답의 `Vary: Origin` 때문에 기존 Worker가 모든 응답을 캐시 제외하고 있었습니다. 요청 Origin을 캐시 키에 포함해 서로 분리하고, 응답의 Vary·CORS 허용 범위를 그대로 보존했습니다. Origin 미지정과 문자열 `null`도 구분합니다. 인증·오류·쿠키 응답과 지원하지 않는 Vary는 계속 캐시하지 않습니다.

현재가 응답의 최대 1초, 원천 Date/Age와 기존 신선도 제한을 늘리지 않았습니다. 허용 Origin·비허용 Origin·문자열 null·미지정 각 두 번의 실제 조회에서 MISS→HIT를 확인했고, 8개 본문 해시는 동일했습니다. 허용한 Origin에만 CORS 응답이 존재했습니다.

**현재 화면의 API 요청은 VPS 직접 경로를 사용합니다.** 이번 Worker 수정은 호환 API 경로의 캐시를 복구한 것으로, 화면 전체가 그만큼 빨라졌다는 뜻이 아닙니다.

### 100동시 측정

Windows PC 공개 인터넷, Node HTTP/2, 호스트당 TLS 연결 하나와 동시 스트림 100개, 검색어/종목 각 10개입니다. 각 endpoint에서 첫 100회·warm 300회·1.6초 후 100회를 실행했습니다. 변경 전후 각각 2,000응답, 오류 0건입니다. API 버전은 두 부하 시험 모두 v104였고 Worker 변경만 비교했습니다. 독립 TCP 연결 100개 시험은 아닙니다.

| 경로·항목 | 변경 전 warm p95 | 변경 후 warm p95 | 목표 |
|---|---:|---:|---:|
| VPS 검색 | 720.39ms | 678.20ms | 300ms 미달 |
| VPS 상세 요약 | 692.44ms | 1,712.33ms | 500ms 미달 |

Cloudflare 캐시 적중 응답만 별도로 고르면 검색 100개 p95 276.46ms, 상세 200개 p95 239.90ms였습니다. **적중한 응답만의 통과를 전체 성능 목표 통과로 처리하지 않습니다.** warm 검색에는 MISS 200개, 상세에는 MISS 100개가 함께 있습니다. 인터넷·원천 지연 변동이 커 서비스 전체 개선율이나 10배 성능을 주장하지 않습니다.

변경 전 시험은 출력 파일 인자 오류로 원시 표본 저장에 실패했습니다. stdout의 집계 결과를 별도 보존했으며 이 한계를 기록합니다. 변경 후 전체 표본은 저장했습니다. 측정 도구는 잘못된 인자와 저장 경로를 부하 생성 전에 검사하고 완료한 endpoint마다 `.partial`에 표본을 남기도록 수정했습니다. 이 도구 수정 때문에 부하 시험을 반복하지는 않았습니다.
