# v58 — 첫 체결 처리의 과거 조회 축소와 실시간 전달 회귀 검증

공개 앱 버전 `20261004-stream-path-v58`. REST·체결·호가 연결과 기존 저장 자료·시각·공유 링크를 유지했다.

## 실제 병목과 변경

첫 체결의 전일 대비 계산을 위해 해당 종목의 정규화된 수십 년 일봉을 전부 역직렬화하는 경로가 있었다. 이제 원천 체결일을 KST 날짜로 정하고, 정규화 시계열에서 그 날짜보다 앞선 종가 한 건을 역순 limit=1로 조회한다. 같은 날짜의 봉은 이전 종가로 사용하지 않는다. 이전 종가 캐시는 시계열 버전과 연결해 지연 수집·정정 이후 다시 확인한다. 체결일·분모를 조회한 시각으로 바꾸지 않는다. 기존 비정규화 자료 읽기는 호환용으로 유지한다.

서버에 저장된 실제 자료를 읽기만 하는 단일 대조에서:

| 종목 | 이전 읽은 행 | 새 읽은 행 | 이전 조회 | 새 조회 | 종가 일치 |
|---|---:|---:|---:|---:|---|
| 삼성전자 | 13,747 | 1 | 719.57ms | 11.00ms | 276,000원 |
| SK하이닉스 | 3,400 | 1 | 92.03ms | 9.97ms | 1,841,000원 |
| 현대차 | 5,400 | 1 | 810.23ms | 4.38ms | 347,000원 |

단일 DB 읽기 비교이며, 캐시 상태와 다른 동시 작업이 통제된 전체 서비스 시험이 아니다. 수신→화면 지연이나 서비스 10배 개선으로 보고하지 않는다. 실제 시세를 테스트 값으로 덮어쓰지 않았다.

## 스트림 계약

토스 공식 [AsyncAPI](https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json) 1.2.2 원문을 새로 내려받아 확인했다. 체결은 통화·가격·수량·시간을 제공하고, 호가 timestamp는 null이 가능하다. 다른 통화와 유효하지 않은 값은 KRW 시세/호가로 승격하지 않는다. 원문 해시를 보존하고 해당 종목의 마지막 정상 자료를 유지하며, 무효 프레임 하나 때문에 나머지 종목의 연결을 재시작하지 않는다. timestamp 없는 호가에 현재 시장 시각을 만들어 넣지 않는다. 유실 탐지 순서 번호와 매매 방향은 생성하지 않는다.

## 검증

관련 테스트 24개 통과.

- 첫 체결에 수십 년 자료를 읽지 않고 한 건만 조회.
- 같은 날짜 종가 제외, 주말 이후 이전 종가, UTC 시각의 KST 거래일 구분.
- 이전 종가의 후속 정정 반영.
- 공식 형태의 체결·호가 처리와 같은 시각/가격의 독립 체결 보존.
- USD·잘못된 값의 정상 자료 덮어쓰기 방지, 호가 null timestamp 처리.
- 수신 정규화→공유 허브→공개 WebSocket에서 가격·호가 변경 전달.
- 공개 WebSocket 재접속의 최신 스냅샷 복구.

마지막 두 항목은 fixture_non_production 테스트이며 실제 장중 수신 또는 렌더링된 화면 검증을 대신하지 않는다.

실제 공개 WebSocket에서도 삼성전자 snapshot/depth를 받았고 가격은 276,000원, 거래 시각은 2026-10-02 19:59:59 KST였다. 새 장중 체결이 아니라 저장된 마지막 정상 자료다. 호가·체결 ready는 REST 자료 가용 상태이며 스트림 수신 증거와 분리했다. health의 v58과 수집 작업자 상태를 확인했다.

배포 전 실제 구독 승인 20건·거부 0건, 실제 수신 evidence 0건이었다. 배포 후 수신 상태도 별도 감사 파일로 남겼다. 일요일의 구독 승인을 실제 장중 검증으로 보고하지 않는다.

## 남은 전체 완료 조건

실제 거래 세션의 체결·호가 수신, 공개 화면 반영과 단절 후 복구·지연 측정이 남아 있다. 전 종목 전체 과거/404, 전 기업 TTM·주식분할, 배당 기업행사·재투자, 공개 성능·실사용 조건도 완료로 처리하지 않는다.
