# v32 첫 화면 조회 분리와 성능 측정

배포: `20261004-detail-summary-v32`. 기존 웹 빌드와 공개 주소 유지.

## 구현·실제 자료

- `detail-summary:{code}`를 원본 상세 변경과 같은 트랜잭션에서 생성한다. 기업 소개와 실제 핵심 손익 항목만 포함한다.
- 기존 전체 상세·사용자 설정·원본 자료는 보존한다. 요약과 기업·재무·공시 조회에서 필요 없는 전체 수급 이력을 읽지 않는다.
- 기존 2,876개 상세에 요약 생성 완료. 원본 조회 대상 1,069,259,684바이트 대비 요약 67,062,892바이트. 이는 저장된 조회 대상 크기이며 네트워크 응답 크기나 전체 서비스 속도가 아니다.
- 대표 10종목에서 요약과 원본의 대응 필드 일치 확인. 이관은 원본 행 잠금 후 요약을 갱신하며 재개 가능하다. 로컬 반복 이관에서 두 번째 변경 0건 및 원본 revision 보존을 확인했다.
- 관련 API·캐시·분석 테스트 55개 통과. 실제 DB 요약 2,876개 확인. 공개 health 및 배포 실행 검사 통과.

## 공개 성능: 목표 미달

Windows PC → 공개 인터넷 → 같은 VPS 주소. HTTP/2 한 TLS 세션, 100 동시 스트림, 검색어·종목 10개. 첫 100회, 연속 300회, 1.6초 뒤 100회. 수집 작업자는 정상 실행했다. 통제 실험은 아니며 공유 VPS 부하·네트워크 변동이 포함된다.

| p95(ms) | v31 첫/반복/대기 후 | v32 첫/반복/대기 후 |
|---|---|---|
| 검색 | 1351.83 / 872.73 / 1569.18 | 2784.85 / 1148.68 / 1263.02 |
| 상세 요약 | 1705.29 / 1852.36 / 2427.53 | 1989.09 / 3852.39 / 2284.53 |

각 실행 1,000요청 모두 오류 0건. 저장·조회 경로 개선을 공개 속도 개선으로 보고하지 않는다. 검색 300ms·요약 500ms 목표는 미달이다.

서버 내부 HTTP 100동시 요청에서도 검색 p95 801.27~2809.48ms, 요약 1030.31~1829.87ms를 기록했다. HTTP/1.1 내부 측정이라 위 HTTP/2 WAN 결과에서 단순 차감할 수 없다. 별도 상세 생성 30회 프로파일에서는 총 5.78초 중 공통 목록 읽기 5.56초였다. DB revision 조회 자체는 1.51~2.62ms였다.

근거: `work/remaining-v32/{before,after,verification}.json`, `projection-backfill.jsonl`, `origin.jsonl`, `profile.txt`.

## 다음 수정과 미완료

v33에서는 일반 스냅샷의 크기 계산을 위한 JSON 재직렬화를 제거하고 Redis 비사용 조회의 Redis 쓰기도 제거한다. 수집·재무·배당·실시간 증거가 완료된다는 의미는 아니다. 확인 시 실제 스트림 증거 행은 0개였다. 전체 과거 자료·기업행사·TTM 확대·장중 검증·사용성·성능 목표는 남아 있다.

## v33 추가 반영 결과

`20261004-snapshot-read-v33` 공개 활성화 확인. 관련 스냅샷·상세·과거 수급·보완 일봉 테스트 30개 통과(위 55개와 중복 포함). 새 코드에서 Redis 우회 시 읽기와 쓰기 모두 하지 않는지, 일반 스냅샷을 읽으며 JSON을 재직렬화하지 않는지 검사했다.

동일 스크립트·주소·100동시 조건의 공개 재측정(`after-v33.json`):

| p95(ms) | 첫 100회 | 반복 300회 | 1.6초 대기 후 100회 |
|---|---:|---:|---:|
| 검색 | 1519.77 | 855.84 | 1350.06 |
| 상세 요약 | 2113.65 | 1431.25 | 1897.42 |

오류 0/1,000. 반복 상세는 v31 1852.36ms에서 1431.25ms로 낮아졌지만, 첫 상세는 1705.29ms에서 2113.65ms로 높아졌다. 모든 조건이 개선된 것은 아니며 목표와 10배 향상은 달성하지 못했다. 다음 성능 개선은 공통 전체 목록의 변경·재구성 비용을 종목 단위로 분리하는 방향을 검토해야 한다. 수집 작업자를 중단한 결과를 정상 운영 성능으로 바꾸어 보고하지 않는다.
