# v43a — 과거 수집의 잘못된 완료 상태 수정

최종 공개 버전 `20261004-history-status-v43a`. 중간 v43의 개별 상태 저장을 묶음 저장으로 개선했다. 화면·주소·사용자 설정·DB 원본·다른 VPS 서비스를 유지했다.

## 실제로 확인한 오류

운영 큐의 거래 자료 작업은 원천 snapshot의 `status=ready`를 그대로 복사했다. 이 상태는 현재 내려받은 자료를 표시할 수 있다는 뜻이다. `next_until`이 남고 `backfill_complete=false`여도 큐가 ready였으므로 전체 과거 자료 수집이 끝난 것으로 읽힐 수 있었다. 이전 ready 통계를 전체 기간 확보 수로 사용할 수 없다.

`trading_collection_status`를 추가했다. 원천 자료의 표시 상태는 `source_status`로 별도 보존한다. 큐의 ready/no_data는 backfill_complete와 다음 커서 없음이 확인된 경우에만 사용하고, 과거 페이지가 남으면 collecting이다. 최신 조회의 빈 응답은 stale이며 마지막 정상 자료를 유지한다. 정상 과거 수집에서 마지막 빈 페이지를 만난 경우는 기존 행을 보존하면서 실제 마지막 페이지 완료로 처리한다.

기존 오류 상태 13,001건을 정정했다. 이전 작업 기록은 `backfill-status-review`에 보존하며 종목·자료·행 수·커서·재시도 등의 기존 정보를 유지했다. 64개 작업의 이전 기록과 수정은 같은 DB 트랜잭션에 넣는다. 중단되면 해당 묶음 전체를 되돌려 이전 기록만 저장되는 불일치를 막는다. 초기 v43의 개별 커밋은 정정 중 수집 시작을 지연시켰고, v43a에서 묶음 처리로 고쳤다. 수정 실패가 큐 전체를 종료하지 않도록 처리했다.

## 실제 검증

- 관련 테스트 53개 통과: 과거 커서가 남는 작업의 완료 방지, 정상 마지막 빈 페이지, 최신 빈 응답과 stale 보존, 기존 커서·원본 보존, 반복 정정의 중복 방지, 묶음 실패 시 이전 기록과 상태 수정의 원자적 롤백, 기존 거래 자료 조회·페이지 수집 회귀.
- 운영 감사: 정정 기록 13,001개, `ready`인데 미완료/다음 커서가 남은 거래 자료 작업 0개.
- 정정 후 기존 큐의 attempts가 49,384 → 49,385, cursor 2,239 → 2,240으로 전진했다. 진행 키를 초기화하지 않았다. 실제 worker 컨테이너 Running=true와 PID도 확인했다.
- 공개 health 버전 v43a 및 삼성전자 요약 HTTP 200·정확한 종목코드를 확인했다.

근거: `work/remaining-v43/before.json`, `after.json`, `after-batch.json`, `after-final.json`, `after-complete.json`, `verified.json`, `public.json`, `tests.xml`. 중간 감사 결과를 최종 완료 통계로 사용하지 않는다.

## 남은 작업

전 종목 과거 자료는 위 collecting·error·미등록 항목이 해결되기 전까지 전체 완료가 아니다. 계속 기존 공유 토스 클라이언트·호출 예산과 커서로 수집한다. 404 보완, TTM·분할 확대, 배당락일·기업행사·재투자, 실제 거래일 체결/호가/복구, 공개 인터넷 성능·실제 사용자 과제도 남아 있다.

이 버전은 수집 상태의 의미와 마지막 페이지 처리를 바로잡은 변경이다. 미완료 작업을 완료로 승격하거나 공개 성능 목표 통과를 주장하지 않는다.
