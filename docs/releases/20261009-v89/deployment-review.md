# v89 배포 안전 검토

검토일: 2026-10-09 KST. 대상은 `promote_backend_patch.py`와 `deploy-market-backend-patch.py`입니다. 실제 서버 변경은 상위 작업에서 별도로 수행합니다.

## 수정한 문제

| 문제 | 수정 |
|---|---|
| 이전 배포 폴더를 복사한 뒤 덮어쓰면 삭제된 Python 모듈이 다시 포함됨 | `services/market_dashboard`를 복사 대상에서 제외하고 새 소스 전체로 교체 |
| 이전 웹 빌드가 남아 불완전한 웹 패키지의 검증을 통과할 수 있음 | 패키지 자체의 BUILD_ID·종목 페이지·정적 JS·공개 자산을 검사하고 이전 빌드 디렉터리 제외 |
| Docker COPY만으로는 이전 이미지의 웹 파일이 사라지지 않음 | 후보 이미지의 `.next`와 `public`을 제거한 뒤 복사, 실행 사용자 `node` 복원 |
| 패키지 작성 실패 시 미완성 tar 파일이 최종 파일명으로 남음 | `.partial`에 작성 후 원자적으로 교체; 실패하면 기존 완성본 보존 |
| 아카이브가 배포 설정이나 공유 데이터 경로를 덮어쓸 수 있음 | 소스·지정 운영 스크립트·선택한 웹 산출물만 허용; 링크·경로 이탈·중복·과대 파일 차단 |

## 보존·복구 계약

- 배포 대상은 API·수집기와 선택한 웹 서비스로 한정하며 `--no-deps`를 사용합니다.
- PostgreSQL·Redis는 외부 컨테이너이며 식별자가 바뀌면 배포 실패로 처리합니다. DB 복원·삭제·재생성은 하지 않습니다.
- 수집기의 기존 `exited` 상태는 복구 대상으로 허용하되 API나 다른 서비스의 정지는 같은 예외로 허용하지 않습니다.
- 새 버전 점검 실패 시 이전 release 환경변수와 앱 경로를 복원하고 이전 앱 이미지를 재실행합니다.
- 별도 웹 배포가 있었으면 release 포인터에 적힌 오래된 웹 이미지가 아니라 실제 직전에 실행 중이던 이미지를 되돌립니다.
- 전환 후 배포 기록 저장이 실패한 경우에도 포인터와 환경변수를 복원합니다.
- 정상 배포 시에만 `deployment.json`에 active 상태와 이전 수집기 상태를 기록합니다.

## 프런트 런타임 의존성

패치 이미지는 기존 `node_modules`를 재사용합니다. 의존성이 바뀌면 일반적으로 전체 웹 이미지 빌드가 필요합니다.

이번 후보는 상위 작업에서 운영/로컬 의존성을 대조했습니다. Next.js 16.3.1·React 19.2가 같고 추가 항목은 Lightweight Charts 5.0.9 하나였습니다. standalone 폴더를 제외한 `.next/**/*.nft.json`에 이 패키지의 서버 런타임 참조가 없고 클라이언트 번들로 제공되는 점을 확인한 예외입니다. 이는 향후 의존성 변경도 자동 허용한다는 뜻이 아닙니다.

## 실행한 검증

```powershell
.venv/Scripts/python.exe -m ruff check ops/market/promote_backend_patch.py scripts/deploy-market-backend-patch.py tests/test_backend_patch_deployment.py --select E9,F63,F7,F82
```

결과: 회귀검사 **19개 통과**, 해당 문법·치명 오류 검사 통과.

검사에는 아카이브 허용 범위·경로 이탈·링크·중복, 불완전한 빌드, 빌드 중 변경, 패키징 실패, 제거된 소스/자산, 멈춘 수집기, 웹 포함/제외 배포, 점검 실패, 포인터 전환 이후 실패, 환경변수와 DB 파일 보존을 포함했습니다. Docker·SSH·서비스 상태는 모의 처리했고, 파일 복사·추출·패키징은 임시 디렉터리에서 실제 실행했습니다. Windows에서는 fcntl과 배포 포인터 링크만 모의했습니다.

## 실제 배포에서 별도 확인할 사항

이 문서는 VPS 배포·롤백·장중 수신 완료 증거가 아닙니다. 실제 배포 후 실행 이미지·공개 버전·API/웹 동선·수집기 진행·DB/Redis 식별자를 대조해야 합니다. 롤백 명령 성공도 이전 앱의 실제 조회 성공을 대신하지 않습니다.
