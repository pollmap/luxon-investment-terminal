## 추가 구현과 검증 경계

- `worker_heartbeat_loop`: 시장 목록 전체 수집 완료와 무관하게 30초마다 `process_heartbeat_at`만 갱신합니다. 시장 결과의 status·updated_at·개수·단계는 보존합니다. 신호가 120초를 넘으면 프로세스 상태를 degraded로 판정하고, 새 필드가 없는 기존 버전은 이전 updated_at 규칙을 사용합니다.
- `share_basis_review_loop`: 실제 상장 대상 중 기존 `share-basis`가 검증됐고 회사 식별자도 일치하는 종목만 대상으로 삼습니다. 대상 목록을 5분마다 갱신하므로 새로 검토한 기업도 하드코딩 없이 참여합니다. 이전 검토 종료 다음날부터 이미 종료한 최신 가격일까지 거래소 공시(I)를 1페이지씩 수집하며 한 구간은 최대 31일입니다. 장기 중단이 있어도 31일 구간을 순차 완료해 이어갑니다. 원문 해시·정확한 요청 범위·전체 페이지·총건수·종목·접수번호 중복을 검사하고 점검 800·호출 예산·저장 용량 중단을 따릅니다.
- 주식 단위/주식 수 변경 공시가 있으면 review_required로 남깁니다. 합병·회사분할·주식교환·주식이전 및 띄어쓰기 변형도 자동 차단하며 원문 제목은 보존합니다. 완전한 기간에 변경 근거가 없을 때만 기존 검토를 연장하고 이전 버전을 보존합니다.
- 실제 자료 없음 013은 status를 000으로 바꾸지 않습니다. 단일 완전 빈 응답과 정확한 회사·시작일·종료일·공시종류·정정 포함 조건·해시가 확인된 경우만 근거로 사용합니다. 당일 변동 중인 공시 목록은 인증하지 않습니다.

heartbeat·주식 단위 검토 관련 **71개 회귀검사**가 통과했습니다. 새 검토 기업의 자동 참여, 미검토 기업 제외, 장기 중단 후 분할 재개, 합병·분할·교환·이전 구간의 자동 연장 차단도 포함합니다. 자동 연장 루프의 실제 운영 수신은 다음 배포 후 확인해야 하며, DART 점검 중 실제 연장이 완료됐다고 보고하지 않습니다.
