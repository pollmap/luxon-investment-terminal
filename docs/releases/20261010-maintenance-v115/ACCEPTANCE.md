## 운영에 적용한 변경

- 삭제 범위: `20261010-dividend-reconcile-v108`, `20261010-raw-boundary-v111` 두 배포 디렉터리.
- PC 보관본 전체 3,645파일의 해시를 대조하고 배포본 하나를 독립 경로에 실제 복원했습니다.
- 압축 보관본: 101,802,128 B, SHA-256 `ffa19ed85e35e777165adbb9f8beb8f1b60c44265bb9cc46b1965a34f38b2c8a`.
- 제거 전 고유 파일의 할당량: 445,173,760 B. 논리 크기 434,540,669 B와 구분합니다.
- 정리 전후 서버 여유: 16,398,860,288 → 16,815,210,496 B. 다른 정상 쓰기가 병행되므로 전체 여유 증가량은 파일 할당량과 다릅니다.
- v109·v110 재무 복구 버전, v112·v113·v114, 사용 중인 v73·v93을 보존했습니다. DB·원본·다른 프로젝트는 삭제하지 않았습니다.

수정 도구는 `/srv/services/korea-stocks/shared/maintenance-v115/retain_releases.py`에 해시 확인 후 설치해 이번 작업에 사용했습니다. SHA-256은 `ca26cd1332d5120103d318f77840f081a8f4e8b8bf92ba40830d099b515119b5`입니다. 기존 배포 디렉터리를 수정하거나 공개 앱 버전을 바꾸지는 않았습니다. 다음 앱 배포에는 저장소의 수정된 보존 도구가 포함됩니다.

두 공개 주소의 health와 삼성전자 요약 조회 4개가 정리 후 200으로 응답했고 release는 v114와 일치했습니다. 첫 진단에서 잘못 지정한 `/summary` 경로는 404였으며, 실제 계약인 `?view=summary`로 수정했습니다. urllib 요청의 403 이후 기존 배포 검증에 사용하는 httpx로 실제 공개 경로를 확인했습니다. 이를 부하 시험이나 브라우저 사용성 검사로 보고하지 않습니다.

## 유지보수 코드와 실제 검사

`ops/market/compact_restore`로 수신·변환·중단 후 재개·전체 대조 모듈을 옮겼습니다. 원본 archive를 바꾸지 않으며, 시계열 값뿐 아니라 재무 전용 출처도 보존합니다. OS의 정렬 순서 차이가 해시 차이로 나타나지 않도록 명시적 C 정렬을 사용합니다.

실제 PostgreSQL 검사는 **격리 fixture**입니다. 실행 후 해당 클러스터는 정상 종료했습니다. 운영 1,600만여 행 전체가 새 구조로 전환되었다는 뜻이 아닙니다. 신규 수신 모듈은 바이너리 전송 성공과 원본 TOC·독립 복원 검증을 분리합니다. 오류·시간·용량 제한에 걸린 파일은 보존하고 성공으로 승격하지 않습니다.
