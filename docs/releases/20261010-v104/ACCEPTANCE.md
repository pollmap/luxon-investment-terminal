## 실제 운영 반영

투자자·신용·대차·공매도 거래의 전체 이력이 여러 JSON에 반복 저장되던 구조에 요약 저장을 적용했습니다. 이미 보존된 날짜별 원천 시계열에서 필요한 기간만 읽고, 기존 응답을 복원합니다. 원문·정정·원천 행을 삭제하지 않았습니다.

먼저 새 읽기 코드만 배포한 뒤 작업자의 쓰기를 활성화했습니다. 활성화 시 API는 재시작하지 않았습니다. PostgreSQL·Redis·OpenAlgo·정적 화면도 유지했습니다. 저장 형식을 읽지 못하는 이전 앱으로의 롤백은 영속 계약으로 차단했습니다.

- 앱 이미지: `sha256:9efbf29f4817490840e1a8e0b4b342a340854203417a2c00aab29059ad7374db`

절차·보존·롤백 계약은 [거래 자료 저장 구조](../../TRADING_PROJECTION_STORAGE.md)에 정리했습니다.

## 보존한 수급 2개와 수정한 결함

삼성전자·기아의 원천과 `toss-normalized` 수급은 전행 일치하지만, `detail.flows`는 토스 255행과 네이버 5행으로 구성돼 있었습니다. 네이버가 들어간 10월 1·2·6·7·8일은 투자자 수치와 집계 범위가 토스와 다릅니다. 이 자료를 같은 중복 원천으로 간주하지 않고 `legacy_preserved`로 남겼습니다.

독립 검토에서 발견한 다음 결함을 수정한 뒤 원래 재현 사례로 다시 확인했습니다.

- 참조 전환 전부터 원천을 강제로 우선해 기존 과거 행이 빠지는 경로.
- 새 과거 페이지가 들어올 때 기존 출력과 달라져 계속 전환하지 못하는 경로.
- 일부만 저장된 신용 구역이 다른 저장본의 대차 구역을 가리는 경로.
- 활성화 도구에서 셸·환경 파일이 다른 배포 태그를 가리킬 수 있는 경로.

서로 다른 날짜의 기존 자료는 보존하며, 같은 날짜 충돌에서는 기존 normalized 우선순위를 유지합니다. 활성화 도구는 실제 Compose 결과의 API·작업자 이미지와 버전을 시작 전에 대조합니다.

## 배당 원문 재처리

기존 오프라인 기업행사 재처리는 DART 공시를 읽지만, 보존된 현대차 IR 배당 원문은 건너뛰었습니다. 온라인·오프라인이 같은 파서와 종목별 매핑을 사용하도록 연결했습니다. 원문의 URL·해시·최초 관측 시각을 확인하며 보통주와 우선주 3종을 구분합니다.

로컬 실제 원문 검증은 10월 8일 보존 입력으로 수행했습니다. 운영에서는 이미 저장된 별도 원문 `6fdb1f27d1c46295114a7f909da48a9d7e702b0c04477459b855bfd1d2d53a97`, 최초 관측 `2026-10-04T05:38:27.205800+00:00`을 사용했습니다. 두 원문을 같은 관측으로 취급하지 않았습니다.

운영 4종목에서 재처리와 재실행의 멱등성, 공급자 작업 상태 보존을 확인했습니다. 이번 운영 재처리에서 이력 수는 늘지 않았습니다. 현대차의 기존 DART 연계 자료와 우선주별 지급 이력이 이미 존재했으며, 중복 지급 이력을 만들지 않았습니다. 원문의 지급 지연 검토 후보 1개는 종목별 후보로 유지했습니다. 확인되지 않은 배당락일을 채우거나 전체 배당 검증 완료로 바꾸지 않았습니다. 배당 재투자는 추가하지 않았습니다.

## 남은 조건과 저장공간

공유 VPS의 디스크 사용량은 작업 중 90%를 넘었다가 다시 약 88%로 내려왔습니다. 마지막 파일시스템 관측의 여유는 19,154,223,104바이트였습니다. 설정된 보호 정책대로 장기 수집은 `capacity_limited`를 유지하며, 80% 미만과 쓰기 검사 통과 전 임의로 재개하지 않았습니다. 공개 조회는 통과했지만, 이것을 장기 수집 재개로 해석하지 않습니다.

읽기 전용 DB 통계에서 `market_time_series`는 약 26.93GB, `market_snapshots`는 약 1.39GB였습니다. 이력 저장 전체를 이번 JSON 중복 제거만으로 해결했다고 보지 않습니다. 다른 서비스·공용 볼륨·과거 원문·백업을 삭제하거나 DB 전체를 재작성하지 않았습니다.
