# v36 전 종목 과거 일봉 수집의 제한된 페이지 연속 조회

공개 배포: `20261004-history-burst-v36`. 이전 버전: `20261004-memory-timing-v35`.
기존 공개 주소, 프런트엔드 빌드, DB와 다른 VPS 서비스를 보존했다.

## 변경

기존 작업은 종목별 200행 한 페이지를 받은 뒤 2,875종목과 7개 자료 종류를 순환했다. 다음 과거 페이지까지 전체 순환을 기다리는 구조를 줄였다.

- 새 자료 또는 과거 커서 재개는 기본 최대 8페이지를 한 차례에 받는다. `MARKET_TOSS_HISTORY_BURST`는 1~16페이지로 제한한다.
- 기존 자료의 최신 페이지 확인은 한 페이지를 유지한다. 더 오래된 수집 커서를 최신 페이지의 얕은 커서로 덮어쓰지 않는다.
- 기존 단일 작업자·공유 인증·API 그룹별 호출 제한·429 대기·재시도를 유지한다. 추가 토스 인증 소유자나 수집 프로세스를 실행하지 않았다.
- 한 종목의 연속 조회 후 다음 종목으로 이동한다. 기존 전체 순환 및 사용자 관심 요청의 배분을 유지한다.
- 뒤 페이지의 통신 실패, 종목 불일치, 정체 커서, 정상 취소가 발생하면 앞서 검증한 페이지와 그 이후 커서를 같은 저장 경로로 보존한다. 잘못된 페이지는 저장하지 않는다.
- 강제 프로세스 종료까지 모든 페이지를 개별 커밋하는 구조는 아니다. 정상 완료 또는 처리 가능한 예외 때 묶음을 저장하며, 강제 종료 시 미커밋 묶음은 다음 실행에서 다시 받는다. 기존 원본 응답은 보존한다.

주요 코드: `services/market_dashboard/toss_backfill.py`, `services/market_dashboard/toss.py`.

## 검증

관련 테스트 40개 통과. 연속 조회의 상한과 다음 종목 이동, 마지막 페이지에서 조기 종료, 기존 깊은 커서 보존, 실패 뒤 정상 페이지만 보존, 다음 실행의 커서 재개를 검사했다. 모의 자료를 실제 데이터로 집계하지 않았다.

실제 DB 확인 시각: 2026-10-04 14:21:39~14:23:20 KST.
공개 서버의 기존 작업자에 관심 자료 요청만 등록하고, 직접 별도 공급자 호출을 실행하지 않았다.

| 종목·자료 | 이전 행 수 | 이후 행 수 | 이전 최초 일자 | 이후 최초 일자 |
|---|---:|---:|---|---|
| NAVER 수정 일봉 | 400 | 2,000 | 2025-02-13 | 2018-08-07 |
| NAVER 원주가 일봉 | 1,400 | 3,200 | 2021-01-15 | 2013-09-13 |
| 현대차 수정 일봉 | 600 | 2,200 | 2024-04-15 | 2017-10-16 |
| 현대차 원주가 일봉 | 3,000 | 4,600 | 2014-07-11 | 2008-02-05 |

현대차 원주가 자료는 첫 43.46초 관찰 구간에서 1,600행이 늘었다. NAVER 원주가 전체 증가 1,800행에는 별도의 최신/조회 경로 진행이 섞일 수 있으므로 전부 한 차례의 8페이지 결과라고 표현하지 않는다. 모든 위 자료는 여전히 과거 커서가 남아 있으며 전체 기간 완료가 아니다.

재시작 후 기존 전 종목 진행 위치를 유지했다. 최종 attempts 49,106, 전체 cursor 1,981, phase 3, priority_cursor 1,125. 인증 전역 backoff 없이 정상 수집 상태를 확인했다. 공개 health에서 새 release가 일치하고 현대차 요약 응답 200·종목코드 일치 확인.

근거: `work/remaining-v36/tests.xml`, `live-before.json`, `live-after.json`, `live-final.json`, `verification.json`.

## 남은 완료 기준

이번 수정은 일봉 수집 단위 개선이다. 수급·프로그램·대차·신용의 페이지 처리, 전체 404 보완, 전 종목 마지막 페이지와 원문 대조, TTM 분할 범위 확대, 실제 배당 지급일·배당락일·기업행사 및 재투자, 장중 체결·호가·복구·화면 검증은 남아 있다.

DART 작업자에서 일일 요청 예산 소진 로그를 확인했다. 제한을 우회하거나 미수집을 미제공으로 바꾸지 않았다. 일별 재개와 미완료 작업 검증이 필요하다.

공개 100동시 요청 성능은 이번 변경으로 재측정하지 않았다. 직전 v35 측정은 공개 검색·상세 목표 미달이며, 이 수집 변경을 공개 응답 속도 개선으로 보고하지 않는다. 서버 처리와 공개 전송·프록시·엣지 지연을 나누는 후속 작업이 남았다. 실제 아버님 사용 과제도 아직 통과하지 않았다.
