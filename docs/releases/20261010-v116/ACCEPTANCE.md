## 수정 내용과 검사

신규 회귀 26개를 포함한 관련 검사 **94개가 통과**했습니다. 수정 전에는 필수 배열이 빠진 응답에도 오류 없이 수집을 종료하는 문제를 재현했습니다. 이는 공급자가 과거에 잘못된 응답을 보냈거나 현재 저장 자료가 잘못 완료되었다는 증거는 아닙니다. 전체 과거 자료를 다시 완료로 표시하거나 강제로 재수집하지 않습니다.

## 복원 도구

유지보수 패키지에 원본 스냅샷 검증과 새 로컬 PG17 복원 실행기를 추가했습니다. 기본 호출은 오프라인이며 실제 실행은 별도 `--run`과 아카이브·증거·공간·시간 상한이 필요합니다.

- 스냅샷 관련 순수 검사 81개, 로컬 실행기 검사 40개 통과. 기존 검사를 중복 합산한 전체 테스트 수로 표현하지 않습니다.
- 실제 `pg_dump` → 바이너리 수신 → 같은 exported snapshot 원본 대조 → 새 PG에 변환 복원 → 모든 논리값·기존 출처 대조를 **33.281초**에 통과했습니다.
- 격리 fixture는 5행·원래 출처 2개이며 재무 전용 출처를 포함합니다. 새 compact 출처는 원래 출처의 보존 증거와 구분했습니다. 두 클러스터 모두 정상 종료했습니다.
- 처음 실제 실행에서 Windows의 `pg_ctl` 자식이 출력 파이프를 상속해 대기하는 문제를 발견했습니다. 해당 신규 클러스터만 식별 후 종료했고 제어 명령 출력은 일반 파일로 바꾸었습니다. 실제 `pg_restore` 데이터 스트림은 기존 제한 큐를 사용합니다.
- 다음 시도는 계획 공간 증가량 검사에서 중단됐으며 클러스터 종료와 실패 기록을 보존했습니다. 마지막 통과 결과로 이전 실패를 지우지 않았습니다.
