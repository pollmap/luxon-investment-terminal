## 성능

`http-final.json`은 Windows PC에서 공개 HTTPS 주소를 순차 조회한 표본이다. 아래 크기는 gzip 본문이며 서비스 전체 속도 향상 배수로 해석하지 않는다.

| 응답 | 전달량 | 행 |
|---|---:|---:|
| 기간 수익률의 기준 가격 | 690 bytes | 5 |
| 1년 일봉 | 8,686 bytes | 242 |
| 10년 월봉 | 5,126 bytes | 121 |
| 시장 수급 최초 표시 | 12,924 bytes | 30 |

기존 상세 화면이 자동으로 요청하던 전체 `/prices`의 압축 전 본문은 13,777,229 bytes였다. 이번에는 이 자동 요청을 없애고 목적별로 나눴다. 기존 전체 API와 원본 과거 자료는 보존한다. 일별 가격을 수집할 때도 전체 시계열을 읽어 다시 쓰는 대신 수신한 행만 갱신한다.

시장 수급은 기존 900행 응답 363,618 gzip bytes에서 기본 30행 12,924 bytes로 줄였다. 이전 자료는 더 보기로 요청한다. 날짜별 캐시와 최신 환율 캐시는 분리하며, 과거 선택이 현재 값을 덮어쓰지 않는다.

측정 파일: `load-wan.json`, `load-loopback.json`. v24b 측정이며 v24c의 추가 변경은 날짜 입력 폼뿐이다. 공개 인터넷 기준 300/500ms 목표는 **미달**이다. 내부 결과를 공개 환경의 목표 달성으로 바꾸지 않는다. LCP·INP·CLS, 실제 사용자 과제, 10배 향상은 이번 검사로 입증하지 않았다.

## 데이터 감사와 남은 일

`coverage-final.json`은 2,875종목의 **수집 작업 메타데이터** 감사다. 가격 행이 있다는 사실과 원천의 마지막 페이지까지 받은 상태를 구분한다.

- 수정 일봉: 마지막 페이지 확인 74종목, 과거 페이지 남음 2,690종목, 404 미해결 109종목, 빈 응답 1종목, 작업 메타데이터 없음 1종목.
- 투자자 수급: 마지막 페이지 확인 34종목, 과거 페이지 남음 2,730종목, 404 미해결 110종목, 작업 메타데이터 없음 1종목.
- 다른 거래 자료도 과거 커서가 남아 있다. 작업 메타데이터 없음은 실제 저장 행 없음과 같지 않다.
- 삼성전자 수정 일봉 1975-06-12~2026-10-02, 13,747행과 투자자 수급 2019-04-01~2026-10-02, 1,844행은 원천 마지막 페이지 확인 상태다. 원주가 3,000행과 신용·대차는 아직 과거 수집 중이다.
- TTM의 기간·귀속이익·가중평균 주식 수 검증은 갖췄지만 실제 `per_share_basis`를 검증·연결하는 수집 경로가 필요하다. 단순히 기다리면 끝나는 수집 대기로 분류하지 않는다.
- 배당 원문 재처리만으로 실제 지급·배당락·분할 등 전체 기업행사 확보를 대신하지 않는다. 일반 종류주식 표기를 특정 우선주 코드에 자동 배정하지 않는다.
- 실시간은 30개 구독 승인, 최근 실제 이벤트 시각 없음이다. 휴장 중 승인·스냅샷 복구를 장중 실제 체결 검증으로 보고하지 않는다.

## 검사·운영

- 관련 Python 검사 94개, 기존 차트 기간·검색 프록시 Node 검사 10개 통과.
- 수정 TSX 린트, TypeScript, Next 프로덕션 빌드 통과.
- 날짜 선택이 조회 직후 초기화되는 브라우저 문제를 발견하고, 제출된 네이티브 폼 값으로 조건을 읽도록 수정했다. 공개 v24c에서 조건 유지·과거 응답·초기화를 확인했다.
- 시장 기관 수급의 첫 30행(2026-10-02~08-20)에서 더 보기를 눌러 60행(2026-10-02~07-07)으로 확장되는 것을 DOM과 화면으로 확인했다. 기존 최신 행과 선택한 기관 열이 유지됐다.
- 기간별 차트 ETag 재조회 304 확인. 원본 정정·긴 거래정지·월/주 첫 봉·누락 OHLC·이전 20봉 계산 사례를 검사했다.
- 배포 전 DB 덤프 `/srv/services/korea-stocks/backups/market-20261003T104137Z.dump`(526,604,239 bytes)를 별도 DB에 복원해 public 테이블 6개를 확인했다. 운영 DB를 과거 백업으로 덮어쓰지 않았다.
- 기존 공개 주소와 DB를 유지했다. `deployed-health.json`에서 v24c, PostgreSQL, 수집 작업 실행 상태를 확인했다. `runtime-final.json`은 v24b 수집 증거이며 v24c와 동일한 백엔드 변경이다.
- 새 브로커 인증이나 유료 계약은 추가하지 않았다. 감사 시 실행 디렉터리의 키움·한투 전용 모듈은 없었다.
