# v51 — 배당락·실제 지급 연결 확대와 공시별 수집 체크포인트

공개 버전 `20261004-kind-dividends-v51`. 기존 공개 주소·프런트·사용자 저장값·다른 서비스를 유지했다.

## 실제 데이터 연결

KIND의 개별 주권 배당락 안내 원문을 열어 회사명·주식 종류·적용일을 확인했다. 회사 IR의 실제 배당 지급 이력에서 정확한 종목·주식 종류·기준일·금액과 지급일을 대조했다. 기록일에 T+2를 적용하여 배당락일을 추정하지 않았다.

| 종목 | 배당 기준일 | 배당락일 | 실제 지급일 | 주당 배당금 |
|---|---|---|---|---|
| 현대차 005380 | 2025-05-30 | 2025-05-29 | 2025-06-30 | 2,500원 |
| 현대차2우B 005387 | 2025-11-30 | 2025-11-27 | 2025-12-31 | 2,500원 |

두 종목의 확인된 배당은 각각 0건에서 1건으로 늘었다. 기존 현대차우의 확인된 배당 1건은 유지됐다. 현대차3우B나 다른 배당에 이번 날짜를 복사하지 않았다.

- [2우선주B KIND 배당락 안내](https://kind.krx.co.kr/external/2025/11/26/000471/20251126001159/99335.htm)
- [현대자동차 IR 배당 이력](https://www.hyundai.com/worldwide/en/company/ir/stock-information/shareholder-return-policy)

## 개발 변경

KIND 파서의 주식 종류 인식에 보통주식·B형 우선주를 추가하되 검토한 명시적 종목 매핑과 원문 주식 종류가 정확하게 일치해야 한다. 회사·구조·날짜가 달라지면 오류로 남기고 마지막 정상 이벤트는 보존한다.

수집 상태 키를 종목 단위에서 종목+공시 URL 해시 단위로 바꿨다. 한 종목에 여러 배당락 공시가 등록돼도 첫 공시의 성공/재시도 시각 때문에 나머지 공시를 건너뛰지 않는다. 기존 작업 상태는 삭제하지 않고 새 문서별 상태를 추가한다. 이번 등록 원문은 총 세 건이며 KIND 전체 공시 발견 수집기가 완성된 것은 아니다.

## 검증·운영

- 관련 KIND·IR·배당 대조·기업행사·분석 테스트 46개 통과.
- 보통주와 우선주 1·2·3종 혼동 거부, 다른 기준일 거부, 두 공시의 독립 체크포인트와 재호출 억제, 실패 시 기존 이벤트 보존 검증.
- 실제 입력 수정 전 `corporate-events-kind-backup:v51`에 해당 이벤트와 관측 자료를 저장했다. 수집 작업자는 단기 중단하고 별도 실행을 끝낸 뒤 finally에서 재시작했다.
- 원본 HTML과 해시를 저장하고 지급 이력의 관측 ID를 배당락 근거에 연결했다. 이미 저장된 회사 IR 이력을 사용하여 불필요한 DART 요청을 추가하지 않았다.
- 공개 세 종목 events API HTTP 200, 신규 두 건의 배당락·금액·확정 지급일 일치, 공개 health의 v51과 collecting 상태 확인.

근거: `work/remaining-v51/tests.xml`, `actual.json`, `public.json`; 코드 `services/market_dashboard/kind_dividends.py`, `tests/test_kind_dividends.py`.

## 남은 완료 기준

개별 배당 증거가 보완됐지만 각 이벤트 스냅샷의 전체 기업행사 확보 상태는 여전히 false다. 배당 재투자 계산을 사용 가능 상태로 임의 승격하지 않았다. 다른 배당락일·전체 기업행사 확인과 원주가/보유 수량 연결을 이어서 완료해야 한다.

전 종목 과거/404, 기업별 TTM·주식분할 기준 확대, 실제 장중 체결·호가 수신 및 복구, 공개 100동시 성능과 사용자 실사용 검증도 남아 있다. 이번 배포에서 부하 시험은 수행하지 않았고 기존 p95 목표 미달 판정은 유지한다.
