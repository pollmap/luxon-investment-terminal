## 중단된 백업 복원

기존 복원 CLI는 새 DB만 만들 수 있어, 보존된 12,819,200행을 그대로 이어 검증할 명령이 없었습니다. 별도 재개 도구를 추가했습니다.

- 기존 PG17 소유 기록·포트·DB·manifest·codec·아카이브 해시를 확인합니다.
- 파일의 마지막 기록 대신 DB 체크포인트와 실제 저장 행을 기준으로 삼습니다. 이미 저장한 모든 행과 원본 출처를 아카이브 처음부터 다시 비교합니다.
- 이전 실패 결과와 아카이브는 보존하고 새 시도만 별도 경로에 기록합니다.
- 새 DB 초기화·기존 데이터 삭제·운영 접속은 하지 않습니다.
- 총 논리 파일 크기, 추가 드라이브 증가, 최소 여유와 실행 시한을 별도로 제한합니다. 이 감시 장치는 OS 디스크 할당량 기능이 아닙니다.

기존/신규 복원 관련 135개 검사 후 추가 방어를 포함한 최종 재개 검사 36개를 통과했습니다. 작은 실제 PostgreSQL 시험은 파일 ACK보다 DB commit이 앞선 중단 상태에서 저장 행 2개와 원본 출처 2개를 재검증하고, 나머지 3개 행과 최종 논리 해시를 대조했습니다. 41.063초, 약 105MB 증가 후 시험 클러스터를 정상 종료했습니다. 이는 fixture 시험이며 대용량 운영 백업 복원 성공을 의미하지 않습니다.

14:32 KST 기존 대용량 복원을 재개했습니다. 제한은 최대 7,200초·추가 4GiB·총 복원본 12GiB·최소 여유 6GiB입니다. 14:36:24 KST에는 기존 12,819,200행의 재대조 단계이며 최종 결과가 아직 없습니다. 이 아카이브의 기존 운영 쓰기 차단은 종료됐으므로, 복원에 성공하더라도 현재 운영 테이블 삭제·교체의 근거로 재사용하지 않습니다.
