# v114: 원본 저장 실패 방지와 보관 공간 회수

2026-10-10 09:13 KST. **API·수집기·기존 공개 화면·Cloudflare 화면을 v114로 반영했습니다.** 원본 저장 중 디스크 부족이나 중단이 발생할 때 불완전한 파일이 최종 이름으로 남는 경로를 수정했습니다. 전체 자료 확보나 운영 저장 구조 전환은 아직 완료하지 않았습니다.

## 사용자에게 달라지는 점

- 수집 중 저장이 실패하면 완성되지 않은 파일을 정상 원본처럼 공개하지 않습니다. 파일을 모두 쓰고 동기화한 뒤 최종 이름으로 게시하며, 재시도할 수 있습니다.
- 같은 원본을 다시 받거나 동시에 저장해도 최초 URL·수신 시각을 덮어쓰지 않습니다. 기존 정상 자료와 정정 이력을 보존합니다.
- 공개 주소·관심종목·차트 선택·설정은 유지합니다. 이번 배포는 화면 기능을 새로 늘리는 변경이 아닙니다.
- 최신 조회와 별도로 전체 과거 수집은 디스크 보호 때문에 제한 중입니다. 수집이 완료된 것으로 표시하지 않습니다.

## 구현과 검사

원본은 임시 파일에 쓰고 파일 동기화를 마친 뒤, 같은 디렉터리에서 create-only 링크로 게시합니다. POSIX에서는 디렉터리도 동기화합니다. 이미 존재하는 정상 원본은 교체하지 않으며 임시 파일은 정리합니다. 압축 게시·기존 파일 제거에도 디렉터리 동기화를 추가했습니다.

|---|---|
| 원본 저장·압축 회귀 | 113개 통과, 환경별 2개 건너뜀; 용량 부족·fsync 실패·게시 실패·경쟁·재시도 포함 |
| 배포·중복 백업 보존 | 73개 통과 |

Linux 검사는 디스크 가득 참을 `ENOSPC`로 주입한 뒤 최종 파일 부재, 임시 파일 정리, 재시도 성공, 첫 수신 기록 보존을 확인했습니다. 실제 물리적 전원 차단 시험이나 새로운 장중 자료 수신 검증은 아닙니다.

새 원본/보존 코드와 테스트는 Ruff를 통과했습니다. 기존 배포 파일 3개의 이전부터 있던 31개 Ruff 지적은 기준선 대조에서 새로 추가된 항목이 0개였습니다. 저장소 전체 린트·보안 검사를 모두 통과했다는 뜻은 아닙니다.

## 실제 확보한 저장 공간

단위는 파일이 차지하던 **실제 할당 바이트**입니다. 공유 이미지의 표시 크기를 더하거나 논리 용량을 회수량으로 보고하지 않습니다.

|---|---|
| DART 원본 압축 | 16,049건의 원본 해시와 기존 메타데이터를 검증하며 751,058,944 B 회수 |
| 같은 날 중복 백업 1개 정리 | 더 최신 백업과 PC 원본·암호화본·전체 복원 증거를 보존하고 2,372,808,704 B 회수 |
| VPS 합계 | **3,123,867,648 B (약 3.12GB)** |
| PC 복원본 무손실 NTFS 압축 | 파일 7개의 바이트 해시 불변, 4,457,263,104 B 회수; VPS 회수량과 별도 |

중복 백업 정리는 정확한 파일명·해시·최근 외부 복구 영수증·열린 파일 사용 여부를 확인하고 단일 파일에만 적용했습니다. 독립된 일별/주별 복구 시점은 제거하지 않았습니다. 다른 프로젝트·볼륨을 정리하지 않았습니다.

기존 DART 메타데이터 중 **빈 JSON 7건은 보존**했습니다. 연결된 바이너리 7개는 파일명 해시와 일치하지만 URL·최초 수신 시각을 복원할 근거까지 확인한 것은 아닙니다. 새 저장 오류 방지 코드가 이 과거 오류를 복구했다거나, 특정 과거 디스크 장애가 원인이었다고 단정하지 않습니다.

09:13 KST 배포 후 서버 여유는 **16,404,504,576 B**, 보호 기준 사용률 약 **89.40%**입니다. 80% 미만 재개 기준까지 추가로 약 **14.56GB**의 여유가 필요합니다. 압축·정리 이후 앱 배포 및 정상 운영 파일 증가가 있어 작업별 회수량과 전체 디스크 여유의 차이가 있습니다.

## 저장 구조 전환 준비와 남은 조건

별도 PostgreSQL 54432에서 실제 custom dump → `pg_restore`의 COPY 출력 → 압축 staging → 논리 해시 비교를 통과했습니다. 정상 5행·출처 2개(재무 전용 출처 포함)와 중복 키·잘린 스트림·지원하지 않는 헤더·프로세스 실패를 포함한 **7개 검사**입니다. 테스트 후 클러스터는 중지했고 자료와 로그는 보존했습니다. 먼저 실행한 두 차례에서 발견한 명령 옵션·Windows 줄바꿈 문제는 수정했으며 그 실패 로그도 유지합니다.

별도 대상 테이블 잠금 검사 6개도 실제 PostgreSQL에서 통과했습니다. 이것과 이전 16,895,854행 로컬 복원 대조는 **운영 DB의 새 구조 전환을 대신하지 않습니다**. 최신 대상 백업·별도 복원 검증·여유 공간·동시 쓰기 차단을 연결한 전환 도구는 아직 준비 중입니다. 운영 테이블 교체와 과거 수집 재개를 실행하지 않았습니다.
