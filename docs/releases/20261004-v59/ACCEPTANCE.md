# v59 — 전 종목 재무 수집의 호출 배분과 중단 원인 수정

공개 버전 `20261004-financial-throughput-v59`. 기존 자료·관심 설정·프런트엔드·가격/분석 계약을 보존했다.

## 실제 운영 상태와 변경

배포 전 2,875종목의 재무 조회 진행 상태를 검사했다. 조회 기록이 있는 종목은 2,759개, 없는 종목은 116개다. 조회별 상태는 ready 4,245개, no_data 1,216개, error 44개였다. 이는 전체 보고기간 확보율이나 TTM 검증 수가 아니다. 우선주의 회사 식별 문제 등 기록 없음의 원인을 따로 검사해야 하며 자료 미제공으로 일괄 확정하지 않는다.

당일 로컬 사용량 6,000회, 자체 제한 6,000회 때문에 전체 재무 큐가 rate_limited였다. 공급자가 이 계정의 6,000회 한도를 선언한 증거는 없었다. 공식 안내는 일반적으로 20,000회 이상에서 020이 발생하나 별도 한도가 적용될 수 있다고 설명한다. 이 계정의 20,000회 보장으로 해석하지 않는다.

- 배포 설정의 자체 DART 일일 예산을 12,000회로 조정했다. 키 교체나 실제 공급자 제한 우회는 하지 않는다.
- JSON/XML의 실제 020 응답을 원문 보존하고 공유 저장 상태에 기록한다. 다른 기간·수집기에서도 같은 날 추가 요청을 중단한다. 날짜가 바뀌면 새 예산으로 검사한다. 동시에 이미 전송된 요청까지 취소된다고 주장하지 않는다.
- 전체 재무 큐는 매 방문에 배경 종목을 처리하고, 매 다섯 번째 방문에만 관심종목 슬롯을 추가한다. 종목별 최신 화면 요청 경로는 유지한다.
- 숫자 인덱스 대신 다음 종목코드를 함께 저장한다. 신규 상장 삽입과 종목 삭제 이후에도 지정 종목/다음 코드부터 재개한다. 기존 커서는 최초 변환에 사용한다.
- 한도 도달 시 미처리 배경 종목을 유지한다. 수집 중단을 원천 미제공으로 처리하지 않는다.

## 검증

관련 테스트 26개 통과. 관심종목 반복과 배경 진행, 우선 요청 일부 성공 후 예산 중단, 상장 목록 삽입·삭제, 기존 커서 변환, JSON/XML 공급자 제한의 새 수집기 적용, 전일 제한 해제, ZIP 원본 보존, 재무 정정 버전·기간 계산 회귀를 확인했다.

실제 배포 후 사용량은 6,005회/예산 12,000회, 큐는 collecting, 커서는 592→594로 진행했다. 해당 시점에는 provider-limit 기록이 없었다. `recent-source.json`에는 이어서 받은 실제 종목별 최신 재무 조회 결과를 보관했다. 실제 자료 수집 재개를 증명하지만 전체 자료 확보 완료를 뜻하지 않는다.

## 남은 완료 조건

전 종목 전체 과거/404와 회사 식별 보완, 전 기업 TTM·분할 기준, 배당 기업행사/재투자, 실제 장중 수신과 공개 화면 반영, 100동시 공개 성능과 실제 사용자 평가를 별도로 계속 검증한다. 이번 변경을 전체 완료나 전체 서비스 속도 개선으로 보고하지 않는다.
