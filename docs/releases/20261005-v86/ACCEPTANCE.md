# v86 — 백필 만료 오류 재시도 우선순위

## 변경

- 수집 worker는 만료된 오류 작업을 매 다섯 번째 작업 기회에서 먼저 재시도한다. 최근 열어 본 종목과 신규 작업의 우선순위는 유지하되, 지속적인 조회 요청이 오래된 실패를 굶기지 않게 했다.
- 재시도는 기존 호출 한도·지수형 대기·작업 커서·원본 자료 보존을 그대로 사용한다. 오류가 전체 순환을 멈추지 않으며 한 번에 실행하는 작업량도 늘리지 않는다.
- 현재 KOSPI·KOSDAQ 목록 밖 404 정리는 v84의 보존 동작을 유지한다.

## 검증 및 공개 반영

- `tests/test_toss_backfill.py`: 53 passed. 만료 오류가 활성 사용자 요청보다 먼저 선택되고 정상 스캔 위치는 유지되는지 검증했다.
- Ruff `F`/`I`: 통과.
- 다중 지표·TTM·주당 기준·배당·수급 관련 회귀 묶음: 통과.
- API·worker를 `20261005-backfill-retry-priority-v86`으로 배포했다. 배포 도구 결과상 Postgres·Redis·web·OpenAlgo는 교체되지 않았다.
- 공개 health: HTTP 200, `ok`, v86, KOSPI·KOSDAQ 2,766개.
- 검색, 삼성전자 요약, EPS 가치평가, 웹 상세는 배포 직전 v85 공개 검사에서 모두 200이었다. v86 반영 후 health 및 수집 상태를 다시 확인했다.
- 운영에서 `001940` 공매도 과거 조회는 이전 `ConnectTimeout` 오류에서 1,732행·커서 소진·`backfill_complete=true`로 전환됐다. 현재 종목 범위 내 `error` 작업은 0건이다. 기록은 `재시도 운영 확인` (로컬 보존 자료: `../../backfill-retry-priority-v86-20261005.json`)에 있다.
- v84에서 시작한 동일 10분 측정은 완료 작업쌍 +15, matched 6개 과거조회 경로의 459개 성공 응답·61,053 수신 행을 기록했다. 저장 행 계수의 차이는 보정하지 않고 `측정 기록` (로컬 보존 자료: `../../backfill-window-v85-10m-20261005.json`)에 남겼다.

## 미완료

백필은 계속 실행 중이며 과거 페이지 수집과 원본 값 대조가 끝나지 않았다. 검증된 주당 기준은 2,766개 중 3개뿐이다. 배당 지급일·배당락일 원문 보완, 실제 장중 체결·호가 수신 및 장애 복구, 100동시 공개 성능, 실제 사용자 과제도 통과하지 않았다. v86은 전체 완료 선언이 아니다.
