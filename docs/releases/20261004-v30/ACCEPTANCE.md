# v30 과거 자료 수집·조회 I/O 개선

공개 버전: `20261004-history-io-v30`.

- 원본 거래 자료 저장은 전체 이력 재해싱 대신 새 페이지의 행만 갱신한다. 기존 행·출처·커서는 보존한다.
- 프로그램 매매 요약은 최신 한 행만 읽는다. 수집 작업 상태 확인도 전체 이력을 읽지 않고 메타데이터를 사용한다.
- 투자자·프로그램 매매 조회는 요청 날짜 범위만 DB에서 읽으며 전체 확보 범위 표시는 유지한다.
- 수급·신용·대차·공매도 화면용 전체 투영 재생성은 아직 남아 있다. 모든 저장 비용을 제거한 것은 아니다.

## 검증
- 관련 테스트 52개 통과. 5,000행 기저 자료에 1행 추가 시 upsert 입력 1행·프로그램 요약 조회 1행을 검사했다. 모의 자료를 운영 자료로 사용하지 않았다.
- 운영 삼성전자 투자자 자료 1,844행 중 2026년 9월 20행 조회를 비교했다. 기존/새 결과는 전체 확보 범위를 포함해 동일했다.
- 같은 서버 프로세스에서 교대로 5회 수행한 DB 읽기+정규화 중앙값: 전체 조회 114.784ms, 범위 조회 48.264ms. 약 58% 감소이며 공개 인터넷·100동시 요청 성능이나 전체 서비스 속도 측정이 아니다.
- 배포 후 작업자가 과거 수집을 재개해 attempts 25,225에서 프로그램 자료를 계속 수집 중임을 확인했다.
- 근거: `work/remaining-v30/range-benchmark.json`.

## 전체 수집 상태
이번 변경 전 감사에서 대상은 2,875종목, 수정 일봉 마지막 페이지 확인은 74종목이었다. 자료별 404는 109~110종목으로 남아 있다. `work/remaining-v29/coverage-now.json`에 기준 시점과 종류별 상태를 보존했다. 수집 진행을 전체 과거 확보 완료로 보고하지 않는다.
