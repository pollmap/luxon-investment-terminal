# v81 — 시계열 이력 저장의 반복 전체 집계 제거

## 변경

가격 이력 페이지를 쓸 때마다 기존 시계열 전체의 `COUNT/MIN/MAX`를 다시 조회하던 작업을 제거했다. upsert가 반환하는 신규 행 수를 사용해 기존 `row_count`를 증가시키고, 페이지 날짜의 최소·최대와 기존 경계를 비교해 `first_time`·`last_time`을 갱신한다. 레거시 메타데이터 또는 복구가 필요한 경우에는 전체 집계를 한 번 수행한다. 시계열 원본 행, 기존 커서, 스냅샷 형식과 DB 스키마는 변경하지 않았다.

Toss 수집기에는 시계열 저장 경로의 누적 시간과 신규·수정 행 계측을 추가했다. 운영 측정 스크립트는 분당 처리량, 종목별 작업 메타데이터 행 변화, API별 요청·오류·응답시간, DB 튜플 변화와 worker 자원 사용을 기록한다.

## 로컬 검증

- 전체 백엔드 테스트는 계측 필드 추가 전 증분 저장 변경까지 통과했다.
- 계측 추가 후 `test_time_series_incremental.py`, `test_toss.py`, `test_toss_backfill.py`, `test_public_history_preservation.py`, `test_openalgo_bridge.py`를 다시 통과했다.
- Ruff `F` 및 `I001`, 영향 모듈 `py_compile`을 통과했다.
- 증분 append·기존 행 수정·경계 날짜·레거시 메타데이터 복구와 키 없는 Toss 계측 fixture를 확인했다.

## 배포·공개 확인

- API와 worker를 `20261005-incremental-series-v81`로 배포했다.
- 배포 스크립트가 PostgreSQL·Redis·웹·OpenAlgo가 유지됨을 확인했다.
- 공개 HTTPS 확인: health, 삼성전자 검색, 요약, 3,000개 일봉, `/stocks?code=005930`가 모두 HTTP 200이었다. Health는 v81과 유효 종목 2,766개를 보고했다.

## 10분 운영 표본

같은 계측 스크립트로 v80 기준선과 v81 표본을 각각 약 10분 측정했다. 표본은 연속된 환경이지만 백필 커서·처리 중인 종목과 종류가 같지 않아 인과 비교로 취급하지 않는다.

| 분당 관측치 | v80 기준 | v81 이후 | 해석 |
|---|---:|---:|---|
| 성공한 공급자 요청 | 57.58 | 63.97 | v81에서 높았으나 큐 종류·위치 통제 없음 |
| 수신 응답 행 | 7,284 | 7,870 | 신규 DB 행과 다름 |
| `market_time_series` 신규 튜플 | 6,246 | 6,643 | 공유 DB 테이블 튜플 변화 |
| 종료 처리 작업쌍 | 1.295 | 1.694 | 작업 상태 기준, 과거 값 완전성을 뜻하지 않음 |

- v80은 602.35초 동안 요청 578건·응답 행 73,127·신규 튜플 62,707·종료 작업쌍 13건이었다.
- v81은 602.13초 동안 유효 요청 642건·응답 행 78,984·신규 튜플 66,666·수정 튜플 122·종료 작업쌍 17건이었다. 계측 세션이 바뀐 `/api/v1/market-indicators/{symbol}/investor-trading`의 요청 증감은 정확한 델타에서 제외됐다.
- 두 표본 모두 측정된 오류와 429는 0건이었다. v81의 upstream 시간 합계는 568,403.64ms, budget wait 합계 38,348.93ms, raw archive 시간 1,184.05ms, 시계열 저장 경로 누적 시간 9,712.59ms였다. 공유 DB 전체 쿼리 통계는 제공되지 않았다.
- 관측치는 백필 상황이 바뀌는 동안의 한 표본이다. 10배 개선이나 통제된 성능 향상을 증명하지 않는다. 다만 이번 변경에서 제거한 전체 이력 집계가 페이지마다 실행되지 않는다는 점은 코드와 회귀검사로 검증했다.

원본 JSON: `v80 기준 측정` (로컬 보존 자료: `../../backfill-window-v80-baseline-20261005.json`), `v81 측정` (로컬 보존 자료: `../../backfill-window-v81-20261005.json`). 현재 자료 확보 작업 메타데이터: `v81 종목별 확보 감사` (로컬 보존 자료: `../../coverage-v81-20261005.json`).

## 남은 범위

KOSPI·KOSDAQ 대상 2,766개 모두에 대한 과거 자료 수집은 진행 중이다. 자료 종류별 1,989~2,444개가 과거 페이지 대기 상태다. 이 변경은 공급자 응답 속도를 바꾸지 않는다. 전 종목 TTM·최근 가격까지의 분할 검증·현금배당 원문·404 보완·장중 실제 체결/호가 수신·재연결·검색/상세 공개 부하 목표·아버님 PC 실사용은 완료되지 않았다.
