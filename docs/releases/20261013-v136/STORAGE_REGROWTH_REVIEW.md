## 오래된 web 이미지의 실제 정리 효과

서비스 prefix 전체 목록 조회가 이미 두 번 제한 시간을 넘겼으므로 같은 명령을
재시도하지 않았습니다. 대신 알려진 **web 이미지 14개 ID**를 네 개씩 inspect하고,
전체 27개 컨테이너의 실제 Image ID와 대조했습니다. 읽은 이미지 필드는
ID·태그·Size·RootFS.Layers뿐이며 환경변수·인증값은 읽거나 출력하지 않았습니다.

- 과거 web 이미지 13개, 60태그는 현재/정지 컨테이너의 이미지 ID에 연결되지 않았습니다.
- 모든 태그가 `korea-stocks-web:` 소유 범위였지만, **그 모든 RootFS 레이어는
  보호한 v93 fallback 이미지의 레이어 집합 안에 포함**돼 있었습니다.
- fallback ID는 `8d06235ba8d0775b84d999ca9a91d1caf5e500c7273a8758bdf535590f6be348`이며,
  정지된 기존 web 컨테이너 참조도 남아 있습니다.
- 따라서 과거 태그를 지워도 fallback이 보유하는 레이어를 회수할 수 없습니다.
  레이어 회수 가능량은 **0B**입니다. 이미지 설정·태그 메타데이터의 작은 회수량은
  측정하지 않았으므로 0B가 전체 메타데이터까지 포함한 절대 삭제 효과라는 뜻은 아닙니다.

표시 이미지 크기와 태그 수를 합쳐 수GB를 확보할 수 있다고 주장하지 않습니다.
API prefix의 전체 목록·공유 레이어 회수량은 이번에 추가로 조사하지 않았습니다.
