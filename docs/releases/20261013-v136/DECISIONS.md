# Lucian 화면·가격 복구·조회 구조 결정

기준: 2026-10-13 KST. 최종 제품 배포 v139, 소스 `ecae992b7c7acf40d6c109191721a3985a24d30f`. 코스피·코스닥 보통주·우선주, 토스 단일 증권사 연결을 유지합니다.

## 화면

토스의 목록·차트·호가 배치와 네이버의 숫자표를 기존 화면에 통합했습니다. Lucian은 검색, 선택, 패널, 상태 표현의 참고입니다. 자체 차트나 금융 데이터 계약을 데모로 교체하지 않았습니다.

- PC 목록·차트·호가의 경계를 포인터와 방향키로 조절합니다. 좁은 화면에서는 호가가 아래로 이동합니다.
- 검색은 방향키 선택과 한글 조합 중 Enter 방지를 지원합니다. 비교 모드에서만 체크박스를 표시합니다.
- 탭·패널·선택 모션은 180/240/160ms이며 동작 줄이기에서는 즉시 전환합니다. 버튼과 숫자의 위치는 움직이지 않습니다.
- 정상 회사·가격 요약을 유지하면서 해당 영역만 로딩·재시도합니다. 청크 로딩 실패는 배포별 한 번 재시도한 뒤 상태를 보존하는 새로고침을 제공합니다.
- 차트의 날짜 선택은 가장 가까운 실제 봉으로 복원합니다. 확대 범위와 선택 날짜를 도구 변경·크기 변경에서 유지합니다.
- v139는 EPS/OCF 비교 가능 기간과 실제 가격 날짜를 분리합니다. 지표가 바뀌거나 실적이 비어도 가격 날짜를 유지하며, 비교 가능한 과거 날짜로의 이동은 명시적 사용자 버튼으로 제공합니다.
- 재무 표는 최근 세 회계연도를 유지합니다. 기간을 검증하지 못한 값은 같은 연도의 단일 검증 기간에만 배치하며, 같은 계정의 다른 금액·기간 충돌이 있으면 합치지 않습니다. 검증하지 못한 셀의 증감률·이익률은 생성하지 않습니다.

## 가격과 재무

- 가격·분석·OpenAlgo가 동일한 자료 선택기를 사용합니다. 종목·시장·조정 기준이 맞는 자료 중 가장 넓은 실제 구간을 선택하며 첫 비어 있지 않은 짧은 자료를 고르지 않습니다.
- 서로 다른 시장·조정 방식의 시계열을 임의로 이어 붙이지 않습니다. 종가만 있는 구간을 OHLC로 채우지 않습니다.
- 요청·표시·저장 기간과 수집·무결성 검증을 분리합니다. `ready` 또는 기존 `history_complete`만으로 전 종목 완료를 세지 않습니다.
- 최신 갱신·과거 수집·중간 공백의 커서를 분리합니다. 정상 빈 페이지와 형식 오류, 반복·순환 커서를 구분합니다. 유효한 종단 응답만 종단 근거로 남깁니다.
- OpenAlgo의 고정 1990년 시작일을 제거하고 실제 확보 시작일을 사용합니다.
- 실제 재무 기간·회사·단위·회계 기준·원문 접수번호·SHA와 금액이 일치해야 증감 계산에 사용합니다. 수집 시각을 공시 공개 시각으로 사용하지 않습니다.
- 기간·공개 시각·분할 기준이 불명확한 숫자는 표에 남길 수 있지만 비교선과 증감률 계산에는 쓰지 않습니다. 연간과 TTM을 한 선에서 혼합하지 않습니다.

## 조회·실시간

- 검색 후보가 30종목 이하이면 그 종목의 시세·재무 요약만 결합합니다. 다른 종목 갱신은 해당 응답 캐시를 깨지 않습니다. 빈 검색·광범위 검색은 기존 거래대금 정렬 계약을 보존합니다.
- 현재 구현에는 광범위 검색의 전체 시장 조회와 식별 색인 버전 확인 병목이 남습니다. 후보 최적화 자체를 공개 성능 목표 통과로 표현하지 않습니다.
- 시세·호가의 DB 반영을 250ms 단위로 묶습니다. 개별 체결 원문은 별도 보존하고, 동일 시각·가격·수량의 서로 다른 체결을 지우지 않습니다.
- 준비한 반영 묶음의 내부 ID로 부분 실패·모호한 commit 이후 재시도를 중복 반영 없이 처리합니다. 이 ID는 공급자 순서 번호나 무손실 수신 증거가 아닙니다.
- v138은 WebSocket 수신 frame을 JSON 해석 전에 보존하고 원래 바이트의 SHA를 projection에 전달합니다. UTF-8은 기존 검증 reader가 읽는 단일 create-only JSON envelope로 저장하며 비UTF8은 기존 바이너리 경로로 바이트를 보존합니다. 기존 이중 파일은 지우지 않습니다. 이전 v136/v137의 재직렬화 SHA를 수신 바이트 증거로 승격하지 않습니다.
- 선택 커서가 누락되면 유효 행과 이전 커서를 보존하고 미확정 상태를 기록합니다. 명시적 null, Toss 출처·64자리 SHA·회사·종류·시장·조정 문맥을 확인해야 종단 영수증을 기록합니다. 영수증 메타데이터와 전행 검증은 별도입니다. 기존 완료 주장은 `legacy_unverified`로 보존하고 새 검증 근거로 바꾸지 않습니다.
- quote-head 조회에는 서비스 전용 16KiB 부분 인덱스를 concurrent로 추가했습니다. 금융 데이터나 DB·Redis 프로세스를 변경하지 않았습니다.

## 복원과 안전 경계

이전 pending 복원 변경은 새 어댑터의 필수 입력이므로 별도 복원 커밋에 함께 보존합니다. 실행 중 코드를 덮어쓰거나 운영 DB로 전환하지 않습니다.

`indexed_resume.py`는 소유가 확인된 loopback PostgreSQL 17, UTF-8, libc C 데이터베이스·열·기본키 collation을 검사합니다. 네 개의 제한된 count SELECT만 기존 기본키 collation으로 조회하며 실제 EXPLAIN이 정렬·필터 없는 해당 Index Scan을 사용하는 경우만 허용합니다. 인덱스 생성·planner 강제·스키마 변경은 하지 않습니다.

원본 SHA, 정확한 전행 수, 정렬 해시, 소스 참조의 최종 검증은 그대로 유지합니다. prefix checkpoint 행 수는 완료 증거가 아닙니다. 복원 4시간·소유 클러스터 추가6GiB·전체16GiB·C: 최소 여유4GiB를 유지하며, 드라이브 전체 변화는 별도 진단값입니다.

안전한 임시 정리로 VPS 80% 조건을 충족하지 못했으므로 대량 수집을 재개하지 않았습니다. 실패한 보존 압축의 원본·부분 파일도 유지합니다. 배당 재투자·새 차트 라이브러리·별도 그래프 DB를 추가하지 않습니다.

이번 실제 복원은 전역 C: 최소 여유 가드로 중단됐습니다. 기존 행 수 일치와 부분 재생 대조를 전체 정렬 해시 검증으로 승격하지 않습니다. 재생 경로의 임시 typed COPY stage 반복 생성과 원문 반복 검증은 후속 개선 후보입니다. 공간 감소 원인을 확인하지 않은 채 같은 복원을 자동으로 반복하거나 예산을 높이지 않습니다.
