# 주식 장보기 v132 — 저장공간·복원 경계·조회·기업 자료

2026-10-11 KST. 대상 버전 `20261011-stock-shopping-v132`. 전체 완료가 아닌 검증 단위의 배포 기록이다.

## 변경

- 종목 검색은 이름·코드·별칭·초성으로 후보를 찾고 최신 거래대금 순서를 유지한 뒤 최대 30종목만 상세 자료와 결합한다. 순위·조건검색의 전체 시장 계산은 유지한다.
- 기업 정보의 종목별 버전을 사용해 다른 기업의 갱신이 현재 종목 요약을 다시 만들지 않게 한다. 이전 저장 경로와 응답 형식은 유지하며 시세 유효 시간을 늘리지 않는다.
- 같은 토스 API 그룹에 최신·사용자·과거 요청이 함께 대기하면 과거 요청에 4회 중 최소 1회 기회를 준다. 유휴·인증 실패·용량 중단 동안 예약량을 쌓지 않으며 429와 공급자 한도를 우선한다. 전체 API 사용량의 무조건 25% 보장과는 다르다.
- 최초 주식 단위 검토 대기열을 추가했다. 실제 입력 사실·회사·주식 종류·기간·원문 해시와 검토된 보통주 무분할 구간을 다시 대조한 뒤 등록한다. 검토되지 않은 기업과 분할·우선주를 자동 승인하지 않는다.
- 배당 금액·기준일·배당락일·지급일의 확보 상태를 구분한다. 일부 날짜가 없어도 확인된 금액을 유지하고 예정일을 실제 지급일로 승격하지 않는다. 기존 저장 행도 조회 시 같은 상태를 제공한다.
- 새 웹 버전 안내를 추가했다. 자동 새로고침 대신 사용자가 선택하며, 현재 링크·목록 조건·관심 그룹·복귀 위치를 보존한다. 가격 응답의 오프라인 캐시는 추가하지 않았다.

## 저장공간과 복원

삭제 대상은 실행 직전 소유·활성 참조를 확인한 주식 서비스의 비활성 빌드 캐시와 정적 배포본이다. 전체 Docker 정리는 하지 않았다. 현재 배포와 최근 정상 두 정적 배포본, DB·원본·부분 복원 결과·다른 서비스를 보존했다.

- 정확한 빌드 캐시 ID별 정리 2회와 정적 배포본 27개 정리를 수행했다. 전후 공간은 별도 기록으로 남긴다. 동시 운영 쓰기 때문에 명목 크기와 전체 디스크 차이가 같지는 않다.
- 백업 부분 파일이 다른 작업에서 먼저 삭제된 경우만 정상 처리한다. 경로·권한·실제 삭제 실패는 숨기지 않는다.
- PC 직접 압축 백업 도구를 추가했다. 서버에 중복 덤프를 만들지 않고 전송 중 `.partial`, 해시 재검사·덤프 목록 검증 후 완료 파일로 전환한다. 이 검사는 전체 DB 복원 통과를 뜻하지 않는다.
- 복원은 처리 확인·DB 반영·검증 경계를 구분하고 작업 폴더 증가량과 드라이브 전체 감소량을 따로 기록한다. 기존 4시간·6GiB 증가·16GiB 클러스터·최소 여유 4GiB 제한을 유지한다.
- 빌드 후 읽기 preflight는 통과했다. 이 결과는 아카이브 전체 해시 재검증, 실제 복원, 최신 운영 변경분 검증을 대신하지 않는다.

## 검증

- 정적 프로덕션 컴파일·TypeScript·5개 경로 생성 통과. 정적 파일 75개, HTML 자산·PWA·해시 검사 통과. 버전 응답의 `no-store` 헤더 변경 후 메타데이터 해시를 다시 검사했다.
- 실제 PostgreSQL 17의 독립 시험 schema에서 검색 결과·가격 동일성, 종목별 기업 정보 캐시 격리, 4연결·44회 시세 갱신 통과. 시험 schema를 제거했으며 운영 자료를 fixture로 바꾸지 않았다.
- 저장·복원 집중 검사 73개 통과. 최초 fixture 오류 수정 후 재검사 결과이며 정기 백업의 실제 성공을 대신하지 않는다.
- 검색 신규 검사 12개 통과. 기존 94개 중 93개 통과 후 발견한 warm 조회 횟수 회귀를 수정했고 해당 사례와 투영 세대 검사 3개가 통과했다.
- Toss 회귀 86개, 주식단위·배당·기존 worker 묶음 84개, 최종 집중 24개와 인증 URL 차단 검사 통과. 날짜별 배당 상태 후속 검사 14개 통과. 서로 겹치는 묶음을 고유 검사 수로 합산하지 않는다.
- 주요 변경 Python 모듈 Ruff 통과. 기존 개발용 생성 타입 파일 때문에 실패한 원래 작업 폴더의 typecheck와 별개로, 깨끗한 정적 staging의 TypeScript 빌드는 통과했다. 기존 `next-env.d.ts` 변경을 덮어쓰지 않았다.

## 남은 실제 통과 조건

전 종목 수집·TTM·분할·배당 근거 확대, 전체 독립 복원과 최신 변경분, 정기 백업 실제 성공, 실제 거래일 체결·호가 수신, 공개 100연결 목표, 사용자 실사용은 각각 별도 판정한다. 일요일의 구독 승인과 모의 이벤트를 장중 수신으로 세지 않는다. 공간이 80% 미만이고 쓰기가 정상인 경우에만 대량 수집을 재개한다.

이번 변경은 새 기업의 TTM 검증 건수를 늘렸다는 주장이 아니다. 배포·성능·GitHub 결과는 실행 후 이 문서에 추가한다.
