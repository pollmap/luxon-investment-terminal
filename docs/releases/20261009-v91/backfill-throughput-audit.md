# 과거 수집 처리량과 불필요한 유의사항 조회 개선

관측: 2026-10-09 01:02:37~01:19:33 KST. 수정 대상: v91. 측정 세션은 `c7111e066b7b4be4932fb1c5f16485aa`이며 다른 세션 수치를 합치지 않았다.

## 관측 결과

`attempts`는 큐 방문 횟수다. 한 번 방문할 때 최대 16페이지를 순차 처리하므로, 14분 동안 29회 방문했다는 수치를 HTTP 29회로 해석하면 안 된다.

| 범위 | HTTP 요청 | 응답 행 | 요청 경과시간 합계 |
|---|---:|---:|---:|
| 전체 토스 API | 1,204 | 94,509 | 1,771.7초 |
| 종목 캔들·투자자·프로그램·공매도·신용·대차 | 528 | 70,867 | 819.0초 |
| 위 항목 중 종목 캔들 | 194 | 38,418 | 327.1초 |
| 종목 유의사항 | 116 | 해당 없음 | 148.3초 |

API 그룹들은 이미 병렬 실행되므로 시간 합계는 실제 경과시간보다 길 수 있다. 과거 조회와 최신 갱신이 같은 경로에 포함되며, 응답 행은 고유 신규 저장 행을 뜻하지 않는다. 캔들 정규화 저장에서는 28,166개 신규 행과 0개 갱신 행, 쓰기시간 합계 약 15.9초를 관측했다.

관측된 HTTP는 모두 200이었고 429·인증 오류는 없었다. 캔들은 호출당 평균 약 1.69초였다. 같은 세션의 과거 자료 관련 6개 API에서 호출 간격 대기는 약 9.4초, 원본 보관은 약 10.6초였다. 대량 큐 전체 20,125개 조회는 약 528ms였고 시작·재조정 때 수행된다. 종목별 데이터 투영은 측정한 두 종목에서 약 25~967ms로, 16페이지 응답 대기의 합계보다 작았다.

## 수정

요약 조회와 미리 읽기도 종목을 활성 목록에 넣는다. 기존 `TossMarket.run_scheduled`는 해당 모든 종목의 유의사항을 60초마다 재조회했다. 이 요청은 투자자·프로그램·대차 등과 같은 `trading` 그룹 잠금을 사용한다.

활성 목록만을 근거로 유의사항을 예약하는 경로를 제거했다. 실제 상세 화면의 `StockWarnings`가 `/securities/{code}/warnings`를 요청하면 기존 요청 큐에서 처리한다. 상하한가 조회, 유의사항 엔드포인트, 60초 TTL, 재시도와 마지막 정상 자료 보존은 유지했다. 화면 요청 의도는 기존 정책대로 최대 1시간 유지된다. 호출 한도·인증·병렬 수는 변경하지 않았다.

이 변경은 관측 구간의 116회가 모두 사라진다는 뜻이 아니다. 실제 상세를 열어 생성한 요청은 계속 처리되며, 배포 후 동일 조건의 절감량은 별도 측정해야 한다.

## 검증과 제한

- `tests/test_market_request_scheduler.py`, `tests/test_market_recovery_sectors.py`, `tests/test_toss_market.py`: 18개 통과.
- 활성 종목만 있을 때 유의사항 호출 없음, 실제 엔드포인트 요청 시 큐 생성과 조회, TTL 내 중복 방지, 실패 시 기존 자료 유지 검증.

- 기존 `budget_wait_ms`에는 API 그룹 잠금 획득 대기가 포함되지 않았다. 따라서 9.4초를 전체 공급자 대기시간이라고 해석하지 않는다.
- 기존 거래자료 경로에는 시계열 쓰기 계측이 연결되지 않은 곳이 있다. 해당 `time_series_write_ms_total=0`은 미측정이며 실제 비용 0이 아니다.
- 요청 경과시간에는 이벤트 루프 스케줄링이 포함되므로 순수 네트워크 시간으로 보지 않는다. DB 활동 단일 관측에서 잠금 대기가 없었다는 사실로 상시 병목이 없다고 단정하지 않는다.
- 전 종목 수집 완료 예상시간이나 전체 서비스 속도 개선 배수는 산출하지 않았다. 공개 100동시 성능 시험을 이번 작업에서 수행하지 않았다.
