# v75 — 토스 백필 요청 계측

## 목적

백필 `attempts` 증가만으로 처리량을 판단하지 않도록 토스 API 요청·응답·공급자 대기와 원본 보관 지표를 기록한다. 이 배포는 수집 속도를 임의로 높이지 않는다.

## 변경

- 토스 API별 상태 레코드에 세션 ID, 물리 HTTP 요청 수, 검증된 성공 응답 수, 상태 코드별 응답 수, 429·인증 재시도, 실패 종류, 반환 행 수·바이트, 네트워크 시간, 공급자 대기시간, 원본 저장시간을 기록한다.
- 한 번 성공한 뒤 요청이 실패해도 직전 성공 시각과 해시는 유지한다.
- 종목별 요청 파라미터·인증정보는 기록하지 않는다.
- 현재 성공 요청 상태 레코드를 재사용해 성공 호출마다 별도 계측 DB 행을 추가하지 않는다. 오류 상태는 기존 최신 상태 레코드에만 반영된다.
- 저장된 정규화 행 증가는 `market_time_series`의 전후 집계로 별도 측정한다. API 응답 행 수와 저장 행 수를 같은 값으로 취급하지 않는다.

## 로컬 검증

- Toss 요청 pacing, 429 재시도, 성공 응답 행 수, HTTP 404 오류 계측, 직전 성공 해시 보존 테스트를 실행한다.
- 테스트 통과 여부와 실행 명령은 배포 직후 아래 공개/런타임 검증 부분에 기록한다.

## 운영 검증

- 활성화 전 공개 버전과 백엔드 컨테이너 상태를 확인한다.
- 배포 후 API·worker만 변경하고 DB·Redis·web·OpenAlgo가 유지됐는지 컨테이너 ID로 확인한다.
- `/health`, 검색, 종목 요약의 기존 계약을 확인한다.
- 같은 worker 세션의 연속 10분 표본에서 API별 요청·성공·오류·응답 행·바이트, 저장 시계열 행 증가, 백필 작업 완료 변화, 공급자 대기·상류 시간, 프로세스 메모리를 기록한다.
- worker 재시작으로 `session_id`가 바뀌면 그 구간은 하나의 처리량 표본으로 합치지 않는다.

## 결과

배포 상태: 완료. `20261005-toss-request-metrics-v75`을 공개 API·worker에 반영했다. `/health`, 검색, 삼성전자 요약 및 094800 검색·요약이 정상 응답했다. 배포에서 API·worker만 교체했고 PostgreSQL·Redis·web·OpenAlgo 및 VPS의 다른 서비스는 유지했다.

로컬 검증: 관련 테스트 71개 통과. 실행은 `pytest tests/test_toss_request_pacing.py tests/test_toss_market.py tests/test_toss.py tests/test_toss_backfill.py -q`, Ruff 선택 검사 및 `compileall` 통과다.

10분 표본: 2026-10-05 02:36:10~02:46:13 KST, 602.634초. 공개 대상 2,766종목 중 19,362개 종목·자료 작업을 추적했다. 동일 TossClient 세션이 확인된 API에서 물리 요청 639건, 성공 639건, HTTP·네트워크·프로토콜 오류 0건, 429 0건, 응답 행 74,890건, 응답 바이트 19,008,477건을 기록했다. 이는 분당 요청 약 63.62건, 응답 행 약 7,456건이다. `/api/v1/stocks`는 안정된 기준 세션이 없어 정확한 증감에서 제외했다.

백필 완료 작업 쌍은 3,495개에서 3,511개로 16개 증가(분당 1.59개)했고 시도 카운터는 74 증가(분당 7.37회)했다. `market_time_series`의 PostgreSQL 튜플 삽입은 64,192건 증가(분당 약 6,391건)했지만 공유 테이블 집계이므로 백필 전용 신규 행으로 볼 수 없다. 토스 응답 행 수도 저장된 신규 행과 동일하지 않다.

요청 상류시간 합계는 556.829초, 공급자 budget 대기 합계는 37.673초, 원본 보관 시간 합계는 2.162초다. 이 값들은 동시 요청의 누계이므로 벽시계 처리 구간에 단순 합산하지 않는다. worker cgroup CPU 사용량 증가는 303.592 CPU초(한 코어 기준 평균 50.4%)였고 메모리는 시작 866.6MiB, 종료 1,040.1MiB였다. 최고 메모리는 측정하지 않았다. PostgreSQL 문장별 시간 통계는 사용할 수 없었다.

측정은 기존 제한에서 429 없이 수행됐다. 관측만으로 공급자 한도를 추론하거나 요청 속도를 올리지는 않는다. 데이터 수집 처리량 개선의 다음 검증 후보는 endpoint 그룹별 호출 대기·배치 크기와 저장 작업의 병목 분리이며, 같은 커서·자료 무결성을 유지한 제한적 변경 후 동일 조건으로 비교해야 한다. 상세 수치는 `backfill-window-v75-20261005.json` (로컬 보존 자료: `../../backfill-window-v75-20261005.json`)에 기록했다.

## 공개 실적 분석 API 표본

2026-10-05 공개 API에서 삼성전자(005930), SK하이닉스(000660), 현대차(005380)의 EPS·영업현금흐름/주(OCF)·EBITDA/주를 각각 조회했다. 9개 요청은 모두 응답했고 최근 TTM 기간자료도 반환됐다. 비교 계산 경로 점검에는 사용자가 입력한 8배를 사용했다. 이는 진단 입력이며 적정 배수나 추천값이 아니다.

확인된 범위에서 삼성전자·SK하이닉스·현대차의 최신 TTM EPS, 현대차 OCF를 포함한 기간 표는 2026-06-30 자료를 제공한다. 다만 주당 기준 근거의 유효 종료일도 2026-06-30이라 시계열 비교선은 그 이후 가격에 최신 실적을 연결하지 않는다. 예를 들어 현대차 OCF의 2026-06-30 TTM은 -10,379.67원/주, 자료 공개일은 2026-08-14이며 양수 배수 비교선은 만들지 않는다. 기간 표에는 이 실적값을 남기고, 가격 비교선은 검증 가능한 기준까지만 유지한다. 주당 기준을 이후 기간으로 연장 검증하는 작업은 남아 있다.

음수 OCF를 조용히 누락하거나 양수 비교선으로 바꾸지 않도록 차트에 짧은 설명을 추가했다. 비교선이 자료 기준보다 먼저 끝나는 경우 주식 수 기준 종료일도 표시한다. 세 종목 표본 결과와 정확한 숫자는 `live-analysis-matrix-20261005.json` (로컬 보존 자료: `../../live-analysis-matrix-20261005.json`)에 기록했다. 전 종목 지표 검증은 아니다.

## 완료 범위와 남은 항목

계측 기능은 실제 수집량을 측정하기 위한 전제 작업이다. 전 종목 과거 자료, TTM/주식분할 검증, 배당 자료, 실제 장중 이벤트 수신, 공개 부하 성능, 모바일·PC 실사용은 별도 완료 기준으로 유지한다.

현재 확인된 UI 문구 수정은 로컬 빌드·회귀 검증 후 공개 웹에 별도 반영해야 한다. v75 공개 웹은 아직 그 수정본이 아니다.
