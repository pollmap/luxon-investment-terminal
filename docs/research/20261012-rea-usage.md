## 실제 실행과 결과

입력은 프로젝트 전체가 아니라 분석에 필요한 선택 파일의 정확한 사본입니다. `.env`, 인증·서버 설정, 사용자 데이터, `node_modules`, 원본 금융 문서는 포함하지 않았습니다. 23개 원본·사본 SHA가 모두 일치합니다.

```powershell
.venv/Scripts/python.exe work/tools/rea-6.1.0/run-analysis.py
.venv/Scripts/python.exe work/tools/rea-6.1.0/run-trace.py
```

각 스크립트는 REA의 다음 명령을 실행하며, 정적 분석 180초·추적 120초로 제한합니다. 두 명령 모두 종료 코드 0입니다. 대상 JavaScript를 실행하지 않았습니다.

```text
rea analyze-javascript-application <절대 경로/source-snapshot> --json
rea trace-application-feature <절대 경로/evidence/valuation-trace-input.json> --json
```

추적 입력은 전체 저장 Evidence와 `module: components/market/valuation-chart.tsx`, 방향 `both`입니다.

| 검증 | 결과 |
|---|---|
| 정적 분석 | 30.609초, TS/TSX 22개, AST 노드 30,802개 |
| 입력 파싱 오류·범위 잘림 | 각각 0 |
| 구조 그래프 | 노드 175개·연결 317개 |
| 기능 추적 | 17.640초, seed 2개·종단 경로 11개 |
| 구조 범위 | `complete-within-source` — 선택한 사본 내부에 한정 |
| 의미 분석 | `unknown` 및 항목별 `partial`; 동적 호출·외부 의존성은 미확정 |
| 대상 실행·상용 런타임 관측 | 하지 않음 |

양방향 추적은 공통 요청·저장 모듈을 통해 다른 선택 파일까지 연결됩니다. 노드 수가 많은 것을 상용 서비스의 기능 수나 검증된 실행 경로 수로 해석하지 않습니다. 통계의 `modules: 0`은 번들 factory 복원 통계이며 TSX 22개 파싱 실패라는 의미가 아닙니다.

## 기능 확장에 사용할 위치

다음 표는 REA가 기록한 import 관계와 해당 원문을 직접 확인한 결과입니다. API 경로·서버 검증 조건은 동적 template을 포함하므로 원문 확인과 실제 계약 시험이 추가로 필요합니다.

| 역할 | 기존 위치 | 이번 개편에서 사용할 방식 |
|---|---|---|
| 지표·기간·배수 상태 | `valuation-chart.tsx:17` | 새 배수 탐색도 동일 선택 상태 사용; 링크 → 저장값 → 기본값 복원 유지 |
| 실적 조회 | `valuation-chart.tsx:43`, `:66` | `/analysis/metrics`, `/analysis/valuation` 결과 사용. 원천 호출이나 별도 계산기를 브라우저에 추가하지 않음 |
| 다른 종목·지표 결과 차단 | `valuation-chart.tsx:45` | `queryKey`, 종목코드·지표 일치 확인을 새 화면에도 적용 |

| 비교 가능 기간 | `valuation-chart.tsx:76` → `analysis-periods.ts:24` | 가격 전체 기간과 검증된 실적 비교 구간을 나눠 표시 |
| 공통 가격·비교선 | `valuation-chart.tsx:112` → `financial-chart.tsx` | 새 차트 라이브러리 없이 비교선·선택 날짜·거래량 사용 |

단순 관계 지도만으로 함수 실행이나 계산 정확성을 증명하지는 않습니다. 비교선·숫자 표·CSV의 일치, 결측·음수·공개 시점·분할 기준, 선택 날짜·확대 보존은 제품 테스트와 실제 자료에서 검증해야 합니다.

REA의 endpoint 후보에는 `params.get('v_multiple')`, `headers.get('Age')`도 포함됐습니다. 이는 실제 API가 아니므로 자동 추출 후보 개수를 API 연결 완료 개수로 쓰지 않습니다. 동적 종목 경로 역시 자동 목록만으로 전수 검증했다고 표현하지 않습니다.

## 보존한 증거

결과는 git에서 제외된 `work/tools/rea-6.1.0/evidence/`에 있습니다.

## 공개 상용 assets에 대한 후속 시도 — 2026-10-13 KST

초기 우리 코드 23개 입력과 결과 SHA는 그대로 보존했습니다. 이후 공개 HTML의 실제 `script src`에 한정해 경쟁 서비스 분석도 시도했습니다. 로그인·쿠키·인증·CDP·API 호출·차단 우회를 사용하지 않았습니다.

다운로드는 4.672초, JavaScript 합계 7,503,826 bytes로 8MiB·90초 제한 이내입니다. 다른 호스트의 `cdn.tolt.io` script는 제외했습니다. 원문은 git에서 제외된 `work/tools/rea-6.1.0/reference-evidence/`에만 보존하며 제품이나 GitHub에 재배포하지 않습니다.

**공개 runtime의 REA 분석은 90초 제한으로 중단됐습니다.** 실제 비어 있지 않은 5,789-byte 입력으로 `analyze-javascript-application`을 실행했으나 `timeout_90s`, stdout 0 bytes, 완료 Evidence 없음입니다. 성공한 경쟁 서비스 기능 분석으로 세지 않으며 같은 시도를 반복하지 않았습니다. Node heap은 384MiB로 제한했고, 전체 도구 디렉터리는 216,907,365 bytes로 300MiB 이내입니다.

큰 main bundle을 억지로 처리하거나 두 서비스의 전체 기능·차트 계산식을 복구했다고 표현하지 않습니다. 공개 asset의 존재·HTML 연결 관계와 로딩 코드의 관측을 비공개 제품 구조의 증거로 승격하지 않습니다. 기능 설계의 근거는 별도 공개 설명·화면 관찰에 두고, 우리 구현은 기존 검증된 계산·차트 코드를 사용합니다.
