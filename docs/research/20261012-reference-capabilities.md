# FAST Graphs·Simply Wall St 기능 대조와 국내 적용

확인일: 2026-10-12 KST. 공개 공식 도움말·공개 한국 시장 페이지·현재 저장소를 대조했습니다. 로그인한 상용 화면, 유료 기능의 실제 조작, 공급자 내부 API, 현재 운영 DB의 전 종목 입력은 확인하지 않았습니다. 따라서 이 문서는 **공식 설명에서 확인한 기능과 코드상의 구현·입력 조건**을 정리하며, 전체 기능 복제나 실제 데이터 확보 완료를 뜻하지 않습니다.

## 적용 원칙

주식 장보기의 범위는 코스피·코스닥 보통주·우선주, 로그인 없는 PC·모바일 조회입니다. 가격·거래는 토스, 기업 사실은 DART·XBRL·KIND·IR과 검증된 자료를 사용합니다. 비교 서비스의 데이터나 내부 구현을 우리 원천으로 삼지 않습니다.

공통 사용자 과제는 **종목 선택 → 실적과 주가 → 지표·기간 변경 → 실제 수치 확인 → 수급·기업 자료 → 관심 저장·복귀**입니다. 새로운 상위 메뉴보다 기업 분석 안의 지표·표·차트를 보완합니다. 종합점수, 배당 재투자, 주문·계좌, 해외·코넥스는 적용 대상에서 제외합니다.

## 2. 공개 모델 저장소에서 배울 부분

Simply Wall St 도움말은 공식 [Company-Analysis-Model](https://github.com/SimplyWallSt/Company-Analysis-Model)에 연결합니다. 공개된 것은 앱 소스가 아니라 분석 모델 문서입니다. `MODEL.markdown`, `GROWTH.MARKDOWN`, `industry_averages.markdown`은 산식·입력·범위의 대조 자료로 유용합니다. README가 명시하는 라이선스는 **CC BY-NC-SA 4.0**입니다. 이번 작업은 문서의 정의를 참고하며 원문·이미지·구현을 제품에 통째 복사하지 않습니다.

현재 도움말과 모델 문서의 정의가 항상 같지는 않습니다. 예를 들어 과거 모델의 BPS 설명에는 무형자산 차감이 포함되고, ROE 분모도 설명별로 최근 잔액과 평균 잔액이 다릅니다. 우리의 BPS·ROE를 해당 명칭만 보고 바꾸지 말고 독립적인 산식 버전과 입력을 유지해야 합니다. [모델 문서](https://github.com/SimplyWallSt/Company-Analysis-Model/blob/master/MODEL.markdown)

공개 성장 모델에는 과거 사실의 회귀 추세와 기관 수 가중 예상 추세가 구분됩니다. 이는 끝점 CAGR과 다른 수치입니다. 적자 구간의 회귀 수치를 CAGR이라고 표시하거나, 외부 예상이 없는 기업에 계산 전망을 실제 컨센서스로 채우면 안 됩니다. [성장 모델](https://github.com/SimplyWallSt/Company-Analysis-Model/blob/master/GROWTH.MARKDOWN)

REA 저장소·격리 설치·실제 실행·공개 상용 asset 시도의 결과는 [도구 기록](20261012-rea-usage.md)에 있습니다. 자체 코드 정적 분석은 성공했지만 FAST 공개 runtime 분석은 제한 시간으로 중단됐고 Simply Wall St 공개 상세는 403입니다. 이를 두 서비스의 전체 역설계 성공으로 표현하지 않습니다.

## 4. 적용 기능과 다음 입력 과제

아래 1순위는 v134에서 차트·표·CSV·공유 링크와 실제 공개 숫자 대조까지 반영했습니다. 2순위는 별도 회사 전체 조회·지연 요청·근거 표시를 구현했으며, v135는 기존 검증 numerator의 연결을 보완합니다. 실제 순이익·CAPEX·예상실적 이력의 공백은 남습니다. [공개 검증](../releases/20261012-v134/ACCEPTANCE.md).

### 1순위: 실적과 주가 안의 배수 이력

사용자 질문은 ‘실적이 오른 것인가, 시장이 더 높은 배수를 적용한 것인가’입니다. 기존 `valuation_series.series[].multiple`을 재사용하고, **원 단위 주가·비교선과 배 단위 배수**를 별도 축 또는 아래 작은 그래프로 구분합니다. 기본 화면에 강제로 추가하지 않고 ‘배수 이력’을 열었을 때 표시합니다.

- 서버가 `comparison_eligible`로 인정한 양수 지표와 동일 분할·공개 기준만 사용합니다.
- 값이 없으면 선을 끊고 선택 시점에 사유를 표시합니다. 새 요청·새 원천은 필요하지 않습니다.
- 선택 날짜·확대 범위는 기존 차트와 공유합니다.
- CSV에 당시 실제 배수와 선택 배수를 별도 열로 넣고 표·차트와 대조합니다.
- 통과: EPS→OCF→EBITDA 전환 시 단위·명칭·자료가 바뀌며, 결측을 EPS로 대체하지 않습니다. 적자·0·빈 구간의 배수는 생성하지 않습니다.

### 2순위: 이익과 현금흐름의 동일 기간 비교

사용자 질문은 ‘장부상 이익이 실제 현금으로 이어졌는가’입니다. 기업 분석의 기존 실적의 흐름에 **순이익·OCF·설비투자·FCF**를 선택하도록 보완합니다. 총액 차트는 주식 수 기준이 필요한 가격 비교와 별개이며, 동일 기간·회계 기준의 실제 금액을 사용합니다.

- 연간 timeline의 현금흐름 계정을 확장하되 기간·통화·차원·원문이 확인된 사실만 연결합니다.
- FCF는 `OCF − 유형/무형자산 취득 현금지출`이라는 우리 정의를 유지합니다. FCFE·FFO로 바꾸지 않습니다.
- 순이익/OCF 비율을 ‘현금 전환율’로 표시하려면 동일 기간이며 분모가 양수인 경우로 제한합니다. 금융업에 일반 기업의 해석을 자동 적용하지 않습니다.
- TTM은 검증된 네 분기 입력으로만 제공하고 연간 총액과 한 선에서 섞지 않습니다.
- 통과: 실제 총액·금액 차이·증감률과 표/CSV 일치. 누적 현금흐름의 분기 차감, 단위 충돌·중복 계정·음수 사례 검사. 입력 부족은 필요한 항목만 비웁니다.

### 3순위: 예상실적의 근거와 변경 구분

사용자 질문은 ‘언제의 예상이고, 최근에 바뀌었는가’입니다. 현재 예상실적 표에 **대상 회계기간·추정 기준일·평균/중앙값 구분·기관 수**를 추가합니다. 원천이 제공하지 않은 기관 수나 최고·최저를 만들어 넣지 않습니다.

- 최신 추정과 과거 스냅샷을 분리하고 ‘추정 변경’을 입력이 있는 기간만 제공합니다.
- 발표 직전 추정 스냅샷이 있어야 실적과 예상의 차이를 계산합니다. 현재 추정으로 과거 정확도를 만들지 않습니다.
- 사용자 성장 가정은 외부 예상과 별도 표시합니다.
- 통과: 기간·기준일·회사 연결 오류 0건, 없는 예상은 빈 상태, 단일 기업 실패가 가격·다른 기업 자료를 지우지 않음.

## 5. 이번 단계의 끝내는 기준

위 1순위는 기존 검증 응답을 활용하므로 가장 먼저 작게 구현·회귀 검사할 수 있습니다. 2·3순위는 실제 입력을 점검한 뒤 해당 자료가 있는 기업부터 연결합니다. 재무건전성·동종 재무 비교는 후속 작업이며, 차입금·부채·이자 범위와 비교 기간부터 정해야 합니다.

각 후보는 **구현 / 실제 입력 대조 / PC·모바일 조작 / 공개 반영**을 따로 기록합니다. 신규 메뉴 개수, 연구 문서 작성, 계산 함수 존재만으로 완료 처리하지 않습니다. 저장공간·백업 복원·장중 수신·100동시 요청 목표는 이 조사로 통과하지 않으며 기존 완료 기준에 남습니다.
