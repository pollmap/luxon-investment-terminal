# 거래 자료의 요약 저장과 기간 조회

투자자·신용·대차·공매도 거래의 과거 자료는 기존 `market_time_series`의 날짜별 원천 행을 기준으로 사용합니다. 새 정규화 테이블을 만들어 같은 이력을 한 번 더 복제하지 않습니다. `detail`, `financing`, `short-selling`, `toss-normalized` JSON은 검증된 필드에 한해 최근 값과 원천 참조로 줄입니다.

## 보존과 전환

기존 JSON과 새 `toss-trading-reference-v1`을 함께 읽습니다. 최초 전환에서는 전체 소유 필드의 값·날짜·출처를 대조합니다. 이미 새 페이지가 들어온 경우에는 이전 Toss 출력의 소유 필드 해시와 원천 근거를 추가로 확인합니다. 판별할 수 없는 자료는 기존 상태로 보존하며, 다른 자료 제공자의 행을 삭제하거나 토스 출처로 바꾸지 않습니다.

양쪽 호환 저장본에 남은 서로 다른 과거 날짜는 읽을 때 보존합니다. 같은 날짜의 충돌에서는 기존 normalized 우선순위를 유지합니다. 신용·대주·대차는 각 구역별로 정상 자료를 선택합니다. 공매도 거래를 바꿀 때 KRX 잔고 자료를 지우지 않습니다.

전환은 소유 필드만 변경하고 회사 소개 등 공용 JSON의 다른 필드는 보존합니다. 입력·출력 revision을 다시 확인하고 같은 트랜잭션에서 두 호환 저장본과 검증 기록을 변경합니다. 원본 행·원문·출처 참조는 삭제하지 않습니다.

## 조회 계약

- `financing?period=month` 등은 각 구역의 실제 마지막 관측일에서 기간을 계산합니다. 같은 응답 안의 대차·신용 마지막 날짜가 다를 수 있습니다.
- 전환된 필드는 `(series, time)` 기본키로 필요한 기간만 읽습니다. 전체 기간 요청은 전체 원천을 읽습니다.
- 원천 참조가 없는 기존 JSON은 계속 읽을 수 있습니다. 전환하지 않은 자료의 용량·조회 비용이 이미 줄었다고 보고하지 않습니다.
- 원천 행의 출처 바이트·해시를 복원·검증합니다. 원천 식별자·형식·기간 경계가 맞지 않으면 오류로 구분합니다. 양끝 조회만으로 중간 행 삭제까지 검증했다고 간주하지 않습니다.
- 조회 중 자료 revision이 바뀌면 한 번 다시 읽고, 계속 바뀌면 부분 오류로 처리합니다. 시세·기업 자료까지 함께 지우지 않습니다.
- 공개 표·차트의 필드·단위·결측 의미를 유지합니다. 저장 참조나 내부 오류를 공개 응답에 노출하지 않습니다.
- 전체 상세·수급 응답의 캐시 검증값에 해당 원천 revision을 포함합니다. 수집 예약 오류가 정상 조회를 막지 않도록 응답 이후 별도 작업으로 처리합니다.

## 활성화와 되돌리기

쓰기 기본값은 `MARKET_COMPACT_TRADING_PROJECTIONS=0`입니다. API와 작업자의 읽기 지원을 먼저 배포한 뒤 `ops/market/enable_trading_projection.py`로 활성화합니다. 이 도구는 현재 이미지, 렌더링한 Compose 이미지·환경의 버전 일치, 영속 저장 계약을 확인하고 작업자만 재시작합니다.

활성화 전 `shared/data/storage-format.json`에 필요한 읽기 형식을 추가합니다. 작업자 재시작 이후 오류가 생겨도 이 요구사항은 지우지 않습니다. 이미 저장된 참조를 읽지 못하는 이전 앱으로의 롤백은 배포기가 거부합니다. 문제 시 새 쓰기를 끄고 읽기 호환 버전을 유지합니다. 과거 DB 복원을 자동으로 수행하지 않습니다.

## 검증 범위

fixture 회귀는 누락·정정·구역별 기간·0과 결측·다른 원천·동시 쓰기·부분 실패·참조 손상을 검사합니다. 실제 자료 검증은 특정 시점의 원천과 JSON을 읽기 전용으로 추출해 격리 DB에서 변환하고, 전체 조회 결과와 원천 해시를 비교합니다. 이후 운영에서는 제한된 종목부터 공개 응답·작업자 상태를 확인합니다.

JSON 바이트 감소, 읽은 행 수, PostgreSQL 파일 크기, 공개 인터넷 응답 속도는 별도 지표입니다. 요약 저장으로 기존 테이블 파일이 즉시 운영체제에 반환되는 것은 아닙니다. `VACUUM FULL` 등 전체 테이블 재작성은 이 전환에 포함하지 않습니다. 배포별 실제 수치는 해당 `ACCEPTANCE.md`에 기록합니다.
