## Canonical Source Trace Contract

`packages/core/source_trace.py` is the canonical Pydantic v2 contract for
financial provenance. Backend-specific schemas should import this model instead
of redefining a looser trace shape.

Storage-ready datapoints must provide these fields:

| Field | Meaning |
|---|---|
| `source` | Canonical source system, for example `SEC_EDGAR`, `OPENDART`, `EDINET`, `JQUANTS`, `FRED`, `USER_CSV`, or `TEST_FIXTURE` |
| `source_document_id` | Source document, raw object, or logical import document id. Durable storage now requires this; repository paths backfill a logical id from source, filing id, and period when no database FK exists |
| `filing_id` | Filing accession, document id, raw object id, or user import id |
| `form` | Filing/report form when applicable, such as `10-K`, `8-K`, `DART_REPORT`, `JQUANTS_STATEMENTS` |
| `period` | Normalized period key, such as `FY2024`, `2024Q4`, or an ISO observation date |
| `available_at` | Point-in-time timestamp when the source became usable for calculations; derived from `accepted_at`, `filed_at`, or `ingested_at` when possible |
| `unit` | Source or normalized unit, such as `USD/share`, `KRW`, `percent`, or `document` |
| `currency` | Currency code when financial, otherwise the relevant reporting currency |
| `method` | Extraction or derivation method, such as `company_reported`, `xbrl_reconstructed`, `gaap_fallback`, `manual`, or `deterministic_formula` |
| `formula` | Human-readable deterministic formula or source tag path |
| `input_fact_ids` | Source fact ids used by derived metrics |
| `adjustments` | Adjustment ids or labels used by adjusted EPS bridges |
| `confidence` | 0 to 1 confidence score |
| `quality_flags` | Flags such as `fixture_non_production`, `gaap_fallback`, `inferred_tax_effect`, `recurring_adjustment`, or `asymmetric_adjustment` |
| `version` | Version number for append-only/restatement-aware storage |
| `supersedes` | Optional previous version replaced by a later source/restatement |

The model accepts legacy aliases such as `source_type`, `accession_number`, and
`form_type`, but persistence code should call `assert_storage_ready()` before a
fact, metric, adjustment, chart run, or audit row is promoted to durable storage.
Quality validation also uses this canonical contract. Legacy `source_type`
remains accepted as an alias for `source`, but passing traces must expose a
calculation or extraction `method` so Data Audit can distinguish company
reported, reconstructed, fallback, forecast, and derived rows.

`TEST_FIXTURE` traces are allowed only for software tests and local demos. They
must keep `fixture_non_production` in `quality_flags` and must not be promoted
as research or production evidence.

Production source coverage treats `metric_values` as core readiness evidence.
Each ticker needs valuation-ready metric rows in addition to adjusted EPS,
prices, and source documents so GAAP EPS, revenue/share, FCF/share, book/share,
and related selector paths are not marked deploy-ready while empty.
The source coverage summary also exposes `missing_by_requirement` to group
missing tickers by `adjusted_earnings`, `price_bars`, `financial_metrics`,
`source_evidence`, or `consensus_forecast`.
Coverage ticker `counts` also include optional `market_cap_years` and
`listed_shares_years` when price source traces, such as FinanceData marcap,
carry market-capitalization and listed-share evidence. These improve Company
Terminal and Data Audit quality but do not block core readiness by themselves.
When available, Company Terminal snapshots expose `market_cap` and
`listed_shares` from the latest price source trace. FinanceData marcap
`Marcap` values are normalized to KRW market capitalization before storage. The
ingestion path cross-checks raw `Marcap` against `Close * Stocks`; if the raw
value already matches KRW it is stored directly, and if the raw value matches
KRW millions it is multiplied by 1,000,000. The detected raw unit and formula
are recorded in `market_cap_source_trace`.

`source_coverage.remediation.next_actions` is the operator-facing runbook for
closing those gaps. Each action contains an `id`, `priority`, `requirements`,
`tickers`, `description`, `cli_commands`, and `github_actions` payload. Actions
only point to source-backed ingestion paths such as SEC bulk load, adjusted EPS
normalization, Stooq/pykrx/FinanceData marcap/J-Quants price collection,
OpenDART/J-Quants/EDINET filing collection, FnGuide user-export import, or
consensus CSV import.

Market CSV import validates source-backed price and dividend rows before
persistence. It rejects non-positive close prices, negative dividends, invalid
ISO dates, invalid currency codes, missing source ids, and non-HTTP source URLs.
Dry-run mode returns tickers, fiscal years, date range, price row count, dividend
row count, source types, and currencies.

Research metadata import uses `collect-research-metadata` for KR Naver OpenAPI
and Hankyung consensus-list evidence. It stores raw JSON metadata only in
`source_documents` and `raw_objects` with
`storage_policy=metadata_only_no_financial_numbers`. These rows may support
Data Audit and research-link panels, but they are not `metric_values`,
`financial_facts`, `consensus_estimate_snapshots`, or valuation inputs.

`GET /api/v1/companies/{ticker}/research-metadata` exposes those rows to the
terminal as source-backed external research metadata. The endpoint returns an
empty `source_backed_required` payload when Postgres/raw rows are unavailable;
it never substitutes fixture links or generated report references. When a local
raw JSON payload is available, the API expands individual `items` links. When
only DB metadata is available, it returns the source document row, content hash,
source URL, and `source_trace`.

| Field | Meaning |
|---|---|
| `policy` | Always `metadata_only_no_financial_numbers` |
| `financial_numbers_allowed` | Always `false`; external report numbers are not valuation inputs |
| `items[].source` | `naver_search_research` or `hankyung_consensus_metadata` |
| `items[].title` | Link title from raw payload when available, otherwise source-level metadata label |
| `items[].link` | External metadata/result URL when available |
| `items[].content_hash` | Append-only raw payload hash |
| `items[].source_trace` | Required provenance for the metadata row, with `unit=research_metadata` |

## Macro Series API

`GET /api/v1/macro-series` returns source-backed macro and official statistics
observations only. It does not provide fixture rows when Postgres is not
configured.

The web Data Audit tab displays these rows in a Macro Series ledger when the
endpoint returns source-backed observations.

| Field | Meaning |
|---|---|
| `series_id` | Canonical macro series id such as `USREC`, `DGS10`, or an official statistics series id |
| `observation_date` | Observation date normalized from source period |
| `value` | Reported source observation value as a decimal string |
| `unit` | Source unit such as `percent`, `indicator`, or official statistics unit |
| `frequency` | Optional normalized frequency such as `daily`, `monthly`, or `annual` |
| `source` | Source system such as `fred`, `ecos`, `kosis`, or `estat` |
| `source_trace` | Source document, source URL, raw period, formula, method, and quality status |

`GET /api/v1/industry-series` returns source-backed official statistics

The web Data Audit tab displays these rows in an Industry Series ledger when the
endpoint returns source-backed observations.

| Field | Meaning |

## FnGuide / DataGuide User Export

`import-fnguide-export` accepts user-supplied CSV/XLSX files only. It never scrapes FnGuide. The raw file is preserved as `source_type=fnguide_user_export`, and canonical rows are loaded into `metric_values`.

| Field | Meaning |
|---|---|
| `ticker` / `종목코드` | Korean security code, normalized to `000000.KS` |
| `name` / `종목명` | Optional company name |
| `fiscal_year` / `회계연도` | Fiscal year parsed from the export row |
| `fiscal_period` / `분기` | Optional fiscal period, default `FY` |
| `metric_key` / `계정명` / `지표` | Metric label mapped to a canonical key when known |
| `value` / `금액` / `수치` | Source value imported as `metric_values.value` |
| `unit` / `단위` | Optional unit, inferred as `per_share`, `percent`, or `raw` for common metrics |
| `currency` / `통화` | Optional currency, default `KRW` |

Dry-run validates value-bearing rows before persistence. Invalid Korean ticker
codes and invalid currency codes fail the import, blank-value rows are counted
as skipped, and the summary returns content hash, tickers, fiscal years, metric
keys, units, and currencies for operator review.

## J-Quants JP Ingestion

`collect-jquants` collects source-backed JP data from J-Quants API endpoints and
preserves every response as a raw JSON source document.

| Endpoint | Raw form type | Warehouse target | Stored value |
|---|---|---|---|
| `/prices/daily_quotes` | `JQUANTS_DAILY_QUOTES` | `price_bars` | `AdjustmentClose` when available, otherwise `Close` |
| `/fins/statements` | `JQUANTS_STATEMENTS` | `adjusted_earnings`, `metric_values` | reported JP S3 market-standard EPS and statement metrics |
| `/fins/dividend` | `JQUANTS_DIVIDEND` | `dividends` | per-share dividend amount with ex-date/record-date trace |

Each row keeps `source_document_id`, endpoint, local code, source URL, raw
close/dividend fields, method, formula, currency, and quality status in
`source_trace`.

## EDINET JP Filing Ingestion

`collect-edinet` preserves JP annual securities report evidence before any
financial statement normalization.

| EDINET API path | Download type | Raw form type | Stored payload |
|---|---:|---|---|
| `/documents.json` | `type=2` | `EDINET_METADATA_LIST` | JSON metadata list filtered by EDINET code and document type |
| `/documents/{docID}` | `type=5` | `EDINET_XBRL_TO_CSV_ZIP` | ZIP containing XBRL-to-CSV converted files |
| `/documents/{docID}` | `type=1` | `EDINET_XBRL_ZIP` | ZIP containing submitted XBRL documents |

The MVP stores these payloads in `source_documents` and `raw_objects` with
content hash, local path, Blob key, EDINET code, `docID`, `docTypeCode`,
period, submit datetime, and document description. It does not infer JP
financial numbers from EDINET CSV until a mapping layer is explicitly added.

## Consensus Estimate Snapshot

| Field | Meaning |
|---|---|
| `metric_key` | Forecast metric, currently `adjusted_operating_eps` |
| `fiscal_year` | Estimated fiscal year |
| `fiscal_period` | Estimated fiscal period, default `FY` |
| `period_end` | Optional fiscal period end date used for 1Y/2Y scorecard snapshot selection |
| `snapshot_date` | Date when this estimate snapshot was captured |
| `estimate_case` | `low`, `median`, `high`, or `current` |
| `estimate_value` | Estimated per-share metric value |
| `growth_rate_pct` | Optional growth rate used or implied by the estimate |
| `analyst_count` | Optional number of analysts represented by the snapshot |
| `source` | User CSV, vendor, or connector source id |
| `source_url` | Source URL when available; one of this, `source_document_id`, or `filing_id` is required by the importer |
| `source_document_id` | Source document id or operator evidence id; one of this, `source_url`, or `filing_id` is required by the importer |
| `filing_id` | Filing, report, or source package id; one of this, `source_url`, or `source_document_id` is required by the importer |
| `quality_status` | `source_backed_consensus_snapshot`, `source_backed_consensus_snapshots`, `user_provided_consensus_snapshot`, `manual_forecast_assumption`, or warning status |
| `source_trace` | Provenance for the estimate snapshot |

The consensus CSV importer validates these fields before persistence. It stores
`snapshot_date` as the point-in-time `available_at` timestamp so forecast,
revision, and scorecard rows can be audited without using current estimates as
historical evidence. Unknown
estimate cases, non-positive EPS estimates, invalid ISO dates, invalid currency
codes, negative analyst counts, non-HTTP source URLs, missing trace anchors, and
template or fixture-only quality statuses fail fast. FAST Graphs screenshots or
application pages, LLM-generated numbers, fixtures, demos, samples,
placeholders, and templates are blocked as numeric forecast evidence. Dry-run
mode returns import-shape metadata including ticker list, fiscal years, snapshot
dates, estimate case counts, source types, quality statuses, and
external-vs-manual assumption counts. Manual forecast assumption rows must use
`source=manual_forecast_assumption` or
`quality_status=manual_forecast_assumption`, include `notes` explaining the
assumption basis, and still provide `source_url`, `source_document_id`, or
`filing_id`.

`export-consensus-template` writes the same columns for a configurable 1Y-5Y
forecast shell. The production gate template uses `median` rows first, while
low/high scenarios can be added later as separate source-backed rows. The
template leaves `estimate_eps` and `source` blank. This is intentional: the
template is not production evidence and should fail import until the operator
fills source-backed consensus, company guidance, or explicit manual assumptions
and adds `source_url`, `source_document_id`, or `filing_id`.

`consensus-workpaper` writes a Markdown operator checklist for a selected CSV
path. It lists the required ticker-year rows, accepted trace anchors, blocked
evidence, and exact export/validate/import commands without generating any
financial estimates.

Valuation-map forecasts read these snapshots when Postgres is configured.
For local KR development, the API may also read a validated
`storage/imports/consensus_{ticker}.csv` overlay after the KR valuation
warehouse is loaded. If the per-ticker file is absent, local mode falls back to
the Top10 aggregate `storage/imports/consensus_estimates.csv` and selects only
the requested ticker rows. Per-ticker CSV files intentionally take precedence
so focused operator workpapers can override the aggregate local package without
renaming it. This overlay is source-backed E2E evidence for the local terminal
only; protected deployment still requires `import-consensus-csv --persist` into
Postgres/Neon and Blob/source-document promotion. Local source coverage may
therefore report `local CSV forecast overlay ready` while keeping
`production_db_pending=true` and `postgres.reachable=false`. For
`forecast_mode=estimates` and `forecast_mode=normal_multiple`, source-backed
snapshot EPS values are used directly by fiscal year before preset growth proxies.
If a 1Y-5Y forecast year is missing, that year is listed in
`source_trace.missing_consensus_years` and only the deterministic continuity
formula fills the gap.

Production source coverage counts 1Y-5Y forecast readiness using
`consensus_valuation_years`: fiscal years with `metric_key=adjusted_operating_eps`
and `estimate_case` equal to `median` or `current`, limited to import-ready
production quality statuses. Low/high scenario snapshots are useful for
sensitivity views, but they do not satisfy the base valuation-map forecast gate
by themselves.

When source coverage is missing this gate, `remediation.forecast_csv_preflight`
reports the expected local CSV path, whether the file exists, row counts, filled
candidate rows, trace-anchor gaps, covered periods, and the strict validation
command. This preflight is intentionally lightweight and does not replace
`validate-consensus-csv`. It also separates external consensus rows from manual
forecast assumptions; manual rows require explanatory `notes` before they can be
reported as preflight-ready. The preflight readout also reports invalid EPS
values, invalid currency codes, and blocked evidence labels so the UI cannot
show a filled but non-importable forecast package as ready.

## Valuation Line Visibility

The valuation-map API returns a `line_visibility` object so UI and rendered exports can use the same display contract.

The valuation-map API returns `meta.range` for the active historical fiscal-year window. `requested_start_year` and `requested_end_year` preserve the user request, while `start_year`, `end_year`, and `historical_points` describe the actual historical rows used for valuation-map calculations before forecast rows are appended.

The valuation-map API also returns `meta.normal_multiple.window_years`, which records the selected 1FY-20FY historical window used to calculate the blue Normal Multiple line. The formula is `trimmed_mean(price / metric)` over the selected historical fiscal-year window.

The valuation-map API returns `meta.price_points` for the black price line when
source-backed `price_bars` are available. In Postgres mode this is the last
available close for each calendar month inside the active historical range,
with each point carrying `source_trace`. In fixture fallback mode this is
limited to explicitly labeled annual year-end fixture prices and is not
production evidence.

Server-rendered SVG/PNG valuation charts use the same `meta.price_points` price
series and include the price point payload in the chart cache key, so cached
exports do not reuse a chart after source-backed price observations change.
Data Audit exposes the same observations as `price_point.close_price.<YYYY-MM-DD>`
facts so individual black-line price observations can be reviewed with their
source document, period, unit, currency, formula, and quality status.

| Field | Meaning |
|---|---|
| `meta.price_points[].date` | Calendar date of the price observation |
| `meta.price_points[].close_price` | Source-traced close price |
| `meta.price_points[].frequency` | `monthly` for Postgres month-end points or `annual` for fixture fallback |
| `meta.price_points[].source_trace` | Provenance for the close price |
| `meta.price_points_meta.historical_only` | True; forecast rows are excluded from market price observations |

| Field | Meaning |
|---|---|
| `price` | Black historical price line |
| `metric_area` | Green selected metric area |
| `fair_value` | Orange fair value line |
| `normal_multiple` | Blue normal multiple line |
| `current_valuation` | Current selected-metric multiple applied across the chart |
| `custom_valuation` | User-selected custom multiple overlay |
| `custom_valuation_multiple` | Numeric multiple used by `custom_valuation` |
| `dividend_floor` | Dividend floor line |
| `payout_ratio` | Dividend per share divided by selected metric, rendered on ratio scale |
| `dividend_yield` | Dividend per share divided by price, rendered on ratio scale |
| `recession_bands` | FRED USREC-derived event/recession shading bands |
| `forecast` | Forecast region shading |
| `scenario_lines` | User/forecast valuation calculation lines |
| `hidden_scenario_lines` | Individual scenario line labels hidden from chart display/export, for example `18x` |

## Screener

| Field | Meaning |
|---|---|
| `per` | Current price divided by selected EPS metric |
| `normal_pe` | Company-relative normal P/E over available history |
| `roe` / `roic` | Profitability comparison fields |
| `eps_cagr` | Historical EPS CAGR |
| `debt_to_equity` | Leverage filter input |
| `market_cap` | Market capitalization used by size/liquidity-style screener filters when source trace evidence is available |
| `market_cap_usd` | USD-normalized market capitalization for cross-market US/KR/JP comparisons when local market cap and FX traces are available |
| `listed_shares` | Listed shares outstanding carried through from market data source traces |
| `filters.metric_to_value` | Absolute threshold filter such as max P/E, min ROE, min EPS CAGR, max debt/equity, min local market cap, and min USD market cap |
| `filters.metric_to_metric` | Metric-to-metric rule, currently ROE > ROIC when enabled |
| `filters.company_relative` | Relative valuation rule using normal P/E and optional discount |
| `filters.passes_all` | Passes all active filter classes |
| `filter_reasons` | Human-readable evaluation evidence for the row |

Supported query config: `max_per`, `min_roe`, `min_eps_cagr`,
`max_debt_to_equity`, `min_market_cap`, `min_market_cap_usd`,
`relative_discount_pct`, and `require_roe_gt_roic`.
`min_market_cap` compares values in each row's local reporting currency.
`min_market_cap_usd` compares `market_cap_usd`, which is derived from local
market cap and FRED FX observations such as `DEXKOUS` or `DEXJPUS` when present.

## Export Center

| Export | Content |
|---|---|
| `research-report.md` | Markdown rendering of the deterministic report, section evidence, audit facts, and report source trace |
| `research-report.json` | Machine-readable bundle with `manifest`, `report`, and `data_audit`; each audit row includes `trace_sections` |
| `data-audit.csv` | Spreadsheet-ready fact ledger with method, policy, quality, formula, source document, filing id, period, unit, currency, input trace keys, calculation input JSON, and full source trace JSON |

Exports reuse already assembled report and audit payloads. They do not create new
financial numbers and must keep source trace fields visible.

Source-backed Data Audit includes direct `financial_facts.<taxonomy>.<tag>` rows
when SEC bulk warehouse facts are present. These rows show the source-level XBRL
fact before promotion into application-facing `metric_values`.

Data Audit also includes `forecast_assumption.*` rows for valuation-map forecast
configuration. These rows record the selected forecast mode, case, growth rate,
target multiple, analyst count, manual EPS override count, formula, and source
so exported CSV/JSON bundles can reconstruct the assumptions behind the
forward valuation lines.

Forecast assumptions use a forecast-specific `source_document_id` and
`filing_id` such as `{ticker}-{forecast_year}-forecast-assumption`. Upstream
evidence stays in `source_trace.input_source_traces` and
`source_trace.input_source_document_ids`, which keeps the forecast assumption
separate from the latest reported metric or consensus snapshot document.
`ai_review` mode is a deterministic review blend, not numeric generation:
its trace records `llm_generated_numbers=false`, `ai_role=commentary_only`,
and the formula `deterministic review blend: (historical_cagr +
consensus_growth_rate) / 2; no LLM-generated numbers`.

Forecast return and consensus namespaces:

| Fact namespace | Meaning |
|---|---|
| `forecast.price` | Forecast target price, equal to forecast metric times the selected multiple |
| `forecast.price_cagr_pct` | Forecast price CAGR with `start_price`, `target_price`, and `forecast_year` in `source_trace.calculation_inputs` |
| `forecast.total_return_cagr_pct` | Forecast CAGR including `annual_dividend * forecast_year` with calculation inputs in `source_trace` |
| `forecast.margin_of_safety_pct` | Forecast margin of safety with `start_price`, `target_price`, and `forecast_year` in `source_trace.calculation_inputs` |
| `forecast_snapshot.{case}.estimate_eps` | Low/median/high/current point-in-time estimate EPS snapshot used for the consensus case matrix |
| `forecast_case.{case}.target_price` | Bear/base/bull target price derived from snapshot EPS and selected target multiple |
| `forecast_case.{case}.price_cagr_pct` | Bear/base/bull price CAGR from latest historical price to case target price |
| `forecast_case.{case}.total_return_cagr_pct` | Bear/base/bull dividend-inclusive CAGR using latest dividend input |
| `forecast_case.{case}.margin_of_safety_pct` | Bear/base/bull margin of safety versus latest historical price |
| `forecast_assumption.*` | Forecast mode, case, growth, target multiple, manual override count, formula, and source |
| `forecast_scenario.{multiple}x.target_price` | Scenario overlay target price, equal to forecast metric times a visible scenario multiple |

`GET /api/data-audit/{fact_id}` returns the selected fact row plus
`trace_sections`, a compact audit structure for UI and agent clients. Sections
are:

| Section | Purpose |
|---|---|
