# 모바일 종목 상세·수급·공매도 구현

2026-09-26. 구현과 실제 원천 수신을 구분한 기록입니다.

후속 개발에서 대차·신용 화면·API·수집 큐와 실시간 장애 처리를 구현했습니다. 아래 당시의 미구현 항목과 이후 결과는 [후속 구현 기록](financing-implementation.md)으로 구분합니다.

## 사용 흐름

휴대폰 종목 상세는 **시세 / 수급 / 공매도 / 기업정보** 네 메뉴를 사용합니다. 시세에서 요약·차트, 기업정보에서 재무·주주·공시를 선택합니다. PC의 기존 상세 탭은 유지합니다. 관심 버튼은 휴대폰에서 짧게 표시하고 접근 가능한 전체 이름을 유지했습니다.

- 수급: 하루·5·20·60거래일 선택, 개인·기관·외국인 기간 합계, 투자자 선택, 터치/슬라이더/이전·다음 날짜 조회, 외국인 보유율, 접는 일별 표. 확보된 집계일 수와 실제 날짜를 표시합니다. 빠진 값이 있으면 합계를 0으로 채우지 않습니다.
- 증권사별: 매수·매도·순매수 기준 정렬, 상위 10개와 전체 표. 양쪽 수량을 확인할 수 있을 때만 순매수를 계산합니다. 상위 명단에서 빠진 값은 0으로 취급하지 않습니다.
- 공매도: 거래·잔고 분리, 1개월·3개월·1년, 수량·금액·비율 선택, 터치 차트, 일별 표, 설명 패널, 실패 재시도와 마지막 정상 자료 유지.
- 큰 글씨와 다크모드, 핵심 터치 영역 최소 44px, 차트의 날짜 이동을 적용했습니다.

## 수집·API

`GET /api/market/v1/securities/{code}/short-selling?period=quarter`

상장 목록의 종목만 허용하고 조회 종목은 기존 활성 구독 목록에 등록합니다. 사용자 요청은 외부 원천을 직접 호출하지 않고 저장된 결과를 반환합니다. 공개 응답은 날짜·숫자·상태만 담고 원문·출처 추적은 내부에 보존합니다.

`short_selling.py`는 과거 차트·DART 작업과 독립 실행합니다. 현재 조회 종목부터 처리하고 전 종목 커서를 저장합니다. 성공 결과는 6시간, 실패는 5분 후 다시 확인하며 원천별 실패 차단을 적용합니다. 여유 디스크가 기본 1GB 이하이면 배경 수집을 중단하고, 256MB 이하면 활성 종목 수집도 멈춥니다. 기존 데이터를 삭제하지 않습니다.

거래와 잔고는 독립 상태를 가지며 잔고를 거래량으로 채우지 않습니다. 정상 자료 이후 빈 응답이나 오류가 오면 기존 자료를 보존합니다. 수급 수집기도 이미 관측한 날짜를 보존해 최대 260개 집계일을 유지하며 정정 날짜는 최신 관측으로 갱신합니다. 원본 응답은 별도로 남습니다.

### 원천 계약

| 원천 | 역할 | 확인한 계약 |
|---|---|---|
| KRX `finder_stkisu` | 종목코드 → 실제 ISIN | `short_code`, `full_code` 일치 검증 |
| KRX `MDCSTAT30102` | 공매도 거래 | 거래일, 수량·대금·전체 거래량·거래량 비중 |
| KRX `MDCSTAT30502` | 공매도 순보유잔고 | 보고의무 발생일, 잔고수량·금액·비율 |
| KIS `daily-short-sale` | KRX 거래 조회 실패 시 보완 | 일별 체결량 사용, 누적량과 구분, 잔고 생성 안 함 |

정의는 [KRX 개별종목 공매도](https://data.krx.co.kr/contents/MDC/STAT/srt/MDCSTAT300.jsp), 호출·필드 계약은 [pykrx 공개 KRX 어댑터](https://github.com/sharebook-kr/pykrx/blob/master/pykrx/website/krx/market/core.py)와 [한국투자 공식 공매도 예제](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/daily_short_sale)를 확인했습니다. KIS 인증은 기존 거래원 수집기와 공유하며 비밀키나 토큰은 원문 저장·로그에 넣지 않습니다.

명세 확인은 현재 계정의 실제 응답 검증과 다릅니다. 외부 통신이 가능한 환경에서 KRX 현재 필드·권한·시장 범위, KIS 응답 및 제공 기간을 추가 확인해야 합니다. 오류·변경된 응답 스키마를 빈 성공 자료로 승격하지 않습니다.

## 실행

기존 통합 수집기를 실행하면 공매도 큐도 함께 시작됩니다. 별도 점검은 저장소 루트에서 실행합니다.

```powershell
.venv\Scripts\python.exe -m services.market_dashboard.short_selling --once --codes 005930 000660 005935
.venv\Scripts\python.exe -m services.market_dashboard.short_selling
```

키 없이 KRX 공개 응답을 먼저 시도합니다. 기존 `MARKET_KIS_APP_KEY`·`MARKET_KIS_APP_SECRET`이 설정돼 있으면 KIS 거래 보완도 사용합니다. 임의 키나 예시값을 운영 자료로 넣지 않습니다.

## 확인과 제한

로컬 저장 수급·거래원으로 모바일 화면을 실행했고 별도 브라우저 fixture로 공매도 거래/잔고 날짜 분리·0/결측·오류 재시도·패널 뒤로 가기를 검사합니다. fixture는 DB에 저장하지 않습니다.

외부 수집을 삼성전자·SK하이닉스·삼성전자우 대상으로 실행했으나 이 환경에서 HTTP 연결이 `ConnectError`로 실패했고 회로 차단이 나머지 재요청을 억제했습니다. 실제 공매도 수신 성공이나 전 종목 공매도 확보를 주장하지 않습니다. 보고 시차는 실제 보고일을 보존해 처리하며 임의로 이틀을 빼서 날짜를 만들지 않습니다.

브로커 실시간 틱 인증, 대차·신용 전용 수집·화면, 아버님 실기기 사용 과제는 별도 미완료입니다. 공개 서버 배포는 현재 환경의 SSH 제한으로 미수행입니다. 로컬 확인 주소는 `http://127.0.0.1:3216/stocks?code=005930`입니다. 기존 공개 주소를 새 버전으로 간주하지 않습니다.

## 조회 성능 수정

실제 로컬 DB에서 `universe` JSON 37,696,851자와 `enriched` 30,391,858자를 확인했습니다. 디코딩 캐시 한도 32MiB보다 큰 종목 스냅샷이 반복 해석되어, 기존 목록 조립 반복 측정은 약 2,000~2,935ms였습니다.

API의 공통 읽기 모델은 universe/enriched/quotes 세 입력만 유지하고 DB 버전을 대조합니다. 변하지 않은 입력은 재사용하고 시세가 바뀌면 시세 입력만 다시 읽습니다. 사용자별 복제나 제한 없는 캐시 확대는 하지 않았습니다. 서버 시작 시 첫 모델을 미리 구성합니다. 저장소 일반 캐시의 32MiB 예산은 직렬화 크기 예산이며, 이 읽기 모델을 포함한 Python 프로세스 전체 메모리 제한을 뜻하지 않습니다.

SQLite 변경 여부 조회에는 `(key, updated_at)` 커버링 인덱스를 명시해 큰 JSON 행을 읽지 않게 했습니다. 매개변수 바인딩은 유지하고 PostgreSQL 조회는 변경하지 않았습니다. 캐시 확인 간격을 강제로 만료시킨 뒤 변경 없는 목록 조회 6회는 0.06~0.39ms였습니다. 실제 시세 변경 시 새 값이 반영되고 변경 없는 큰 입력을 다시 읽지 않는 회귀 테스트와 실제 SQLite 실행계획 검사를 추가했습니다.

로컬 운영 웹을 통한 검색 응답을 1.1초 간격으로 6회 측정하면 인덱스 적용 전 453~1,144ms, 적용 후 9~99ms였습니다. 첫 요청은 98.53ms, 이후 8.62~11.61ms였고 모두 HTTP 200입니다. 원시 측정은 `mobile-mts-local-search-timing.json`에 보존했습니다. 이는 같은 로컬 저장 데이터 측정이며 인터넷 이용자 응답시간이나 동시 100명 부하 성능으로 일반화하지 않습니다.

웹은 `.next-mobile-release` 운영 빌드로 3216에서 실행하며 개발용 UI를 표시하지 않습니다. 웹 빌드·TypeScript·변경 파일 ESLint와 Python Ruff 검사를 통과했습니다.

관련 Python 테스트 48개와 운영 빌드 브라우저 검사 23개를 모두 통과했습니다. 모바일 큰 글씨·다크모드, 수급·거래원, 공매도 오류 복구, 검색·상세·복귀 검사 결과는 `market-browser-results.json`에 기록했습니다. 아버님 실기기 사용성 검증을 대체하는 결과는 아닙니다.
