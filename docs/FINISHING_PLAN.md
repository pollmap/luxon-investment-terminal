## 목표

코스피·코스닥 보통주·우선주의 검색 → 시세·수급 → 실적과 주가 → 재무·배당·주주·공시 → 관심 저장 → 목록 복귀가 실제 자료를 사용하는 공개 서비스에서 작동한다. 전 종목의 제공 가능한 과거 자료를 확보하고, 계산·실시간·속도·복구를 검증한다. 메뉴 존재와 자동 수집 실행만으로 완료 처리하지 않는다.

코넥스, ETF·ETN, 주문·계좌·로그인·커뮤니티·투자점수, 배당 재투자 비교는 제외한다. 배당금·수익률·지급 이력 및 주식분할 검증은 포함한다. 토스만 증권사 연결로 사용하고 DART·KIND·기업 IR·검증된 공개 자료를 유지한다. 키움·한투 재연결, 새 유료 계약·서버 증설·호스팅 전면 이전을 기본 해결책으로 삼지 않는다.

## 역할과 진행 방식

- 아스트라 단계: 이 계획의 설계 판단과 완료 기준을 고정한다. 이후에는 입력 정의 충돌, 계산 근거 부족, 재현되는 구조적 오류 등 판단이 필요한 쟁점만 검토 대상으로 남긴다.
- 루나 단계: 아래 순서로 코드를 수정하고 실제 자료·관련 검사·공개 환경을 확인한다. 각 작업을 처음부터 다시 기획하지 않는다. 범위가 명확한 수정은 스스로 끝낸다.
- 모델 전환은 사용자가 이 채팅의 모델 선택에서 수행한다. 이 문서는 자동 모델 전환·다른 채팅 생성·별도 에이전트 실행을 뜻하지 않는다.
- 작업마다 변경 → 관련 검증 → 결과 기록을 수행하되, 연관된 수정은 한 배포로 묶는다. 긴급 회귀 수정은 즉시 배포한다. 테스트가 통과하면 근거 없이 같은 검사를 반복하지 않는다.
- 과거 수집은 서버에서 계속 진행한다. 수집을 기다리는 동안 독립적인 계산·UI·운영 검증을 진행하며, 수집 진행을 개발 성과로 대신 보고하지 않는다.
- 같은 원인으로 두 번 해결에 실패하면 재현 입력·예상값·실제값·시도·후보 해결책을 한 번 정리한다. 무한 탐색과 새 대규모 설계로 돌아가지 않는다. 독립 작업은 계속한다.

## 실행 순서

### 1. 수집 처리량 개선과 정확한 확보율

관련 위치: `toss_backfill.py`, `toss.py`, `financial_worker.py`, `time_series.py`, `store.py`.

1. 같은 10분 구간에서 실제 성공 요청/분, 저장 행/분, 완료 작업 수, 공급자 대기·네트워크·DB 시간, 429·실패·메모리를 측정한다. 작업 시도 횟수만 처리량으로 사용하지 않는다.
2. 측정된 가장 큰 병목부터 수정한다. 페이지 추가 때 전체 과거 이력을 다시 읽거나 쓰는 경로, 불필요한 중복 조회, 최신/과거 커서 충돌, 순차 처리로 인한 유휴 시간을 우선 검사한다.
3. 공급자 그룹별 실제 한도 안에서 제한된 동시 처리를 검토한다. 동시 처리 허용 시 종목·자료별 잠금, 공유 인증과 요청 예산, Retry-After, 원자적 체크포인트를 유지한다. 숫자만 올려 밀어 넣지 않는다.
4. DART는 회사별 중복 수집을 줄이고, 검증된 발행회사 연결로 우선주의 회사 자료를 공유한다. 개별 EPS·주식 수·배당·가격은 자동 복사하지 않는다.
5. 수집기는 최신 갱신과 전체 과거 수집을 함께 진행한다. 장기 오류 종목이 다른 종목을 막지 않아야 한다.

통과: 같은 조건에서 실제 처리량 개선이 확인되고 429·자료 유실·중복·서비스 지연이 악화되지 않는다. 중단·재시작 후 같은 커서에서 이어진다. 종목 × 자료 × 기간별 완료/수집 중/오류/근거 있는 미제공을 출력한다. 전체 확보는 원천 마지막 페이지와 저장 기간·무결성을 함께 확인한다.
