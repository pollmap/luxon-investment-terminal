## v11 서버 읽기 보완

기업 소개·재무 응답을 만들 때 원본 XBRL 전체를 읽는 경로도 분리했다. 회사 원본과 두 화면용 읽기 모델을 같은 DB 트랜잭션에서 갱신하고 원본 revision을 함께 저장한다. 기존 자료는 조회 시 원본을 한 번 읽어 화면용 자료를 만들며, 다음 조회는 큰 원본을 읽지 않는다. 원본 revision이 다르면 기존 읽기 모델을 재사용하지 않는다. 원본 삭제·일괄 덮어쓰기는 없다.

추가 검사는 원본을 읽으면 실패하도록 한 조회, 정정의 원자적 갱신, 오래된 읽기 모델의 재생성을 확인한다. 최종 테스트 97개가 모두 통과했다. 공개 v11의 company/fundamentals 조회 및 운영 상태는 public-verification-v11-20261003.json, remaining-runtime-v11-20261003.json에 기록한다.

기본 글씨·1440px 시세 화면에서 차트 영역 높이는 360px, 캔버스 시작은 266.86px였다. 시작 위치 260px 목표는 약 7px 미달이다. 큰 글씨와 테마 검증 후 기존 보통·시스템 설정으로 복원했다.

## v12 재연결 상태 보완

재시작·재연결 시 예전 accepted 목록을 연결 성공처럼 재사용하지 않고 connecting→recovering→subscribing→실제 승인으로 기록한다. 한 종목의 REST 스냅샷 실패가 다른 종목의 구독을 막지 않도록 실패 종목만 30초 후 재시도한다. 개별 복구 스냅샷은 15초로 제한한다. 실제 체결 공백을 채워 넣지 않고 기존 gap 표시를 유지한다. 이 경로의 회귀 검사를 추가했다.
