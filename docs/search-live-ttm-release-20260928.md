## 검색 변경과 측정

- FastAPI에서는 겹치는 동일 검색을 공유하고, 처리 종료 후 다음 요청은 실제 DB revision을 다시 읽는다. 한 요청의 취소가 다른 요청을 취소하지 않는다. 실패 결과는 보관하지 않는다.
- 웹에서는 검색 전용 경로를 Node API Route로 처리한다. 화면·기존 다른 API·WebSocket 주소는 유지한다. [Next.js API Routes](https://nextjs.org/docs/pages/building-your-application/routing/api-routes)
- 동일 검색의 서버 스냅샷은 **원천 조회를 시작한 시점부터 최대 250ms**만 재사용한다. 반복 조회로 만료를 연장하지 않으며 오래 걸린 응답·오류 응답은 저장하지 않는다. 최대 256항목·4MiB다. 상세 시세 스트림과 별개이며, HTTP 응답은 `Cache-Control: no-store`다.
- fetch가 압축을 푼 본문을 그대로 전달하던 중간 구현에서 41,977바이트가 전송되었다. 최종판은 gzip을 한 번 만들어 공유해 **2,569바이트**를 보낸다. 압축을 허용하지 않는 요청은 원래 JSON으로 응답한다.
- GET·HEAD, 잘못된 limit의 422, 과도한 URL의 414, 허용하지 않는 메서드의 405를 실제 웹 경로에서 확인했다. 쿠키·인증 헤더는 상위 API에 보내지 않는다.

기존 Node HTTP 도구, 100개 동시 연결, 경로별 300회, warm cache, gzip 응답 전체 수신 기준이다. 저장된 SQLite 자료를 사용했으며 브라우저 렌더링·실제 Android·인터넷 지연·클라우드 수용량을 뜻하지 않는다. 빌드와 부하 검사는 동시에 실행하지 않았다.

## TTM와 실제 연결

`ttm_backfill.py`는 지정 종목 묶음의 해시를 사용한 독립 커서로 진행한다. 전체 시장의 기존 수집 위치를 초기화하지 않는다. 회사 식별 조회 실패도 오류 종류·단계·다음 재시도 시각을 남기고 마지막 정상 재무를 보존한다.

삼성전자와 SK하이닉스는 각각 기간이 확인된 duration 입력 10개가 있지만 모두 2025-01-01~2025-12-31 연간 자료다. 이 입력으로 연속 네 분기를 만들어내지 않는다. 금액 계정 TTM과 EPS TTM도 구분한다. 합성 분기 fixture로 누적 차감부터 금액 TTM까지 검사했으며 이를 실제 수신이라고 표시하지 않는다.

- DART 키의 존재만 확인했고 비밀값을 출력하지 않았다. 실제 회사 조회에서 `ConnectError → OSError → PermissionError(errno=13, winerror=5)`가 발생했다. 잘못된 키라는 결론은 내리지 않는다.
- 키움 키·한투 키·KRX 키는 현재 런타임 설정에 없었다. 키움 홈 재시도는 CD-14005, 한투 공식 신청 화면은 보안프로그램 설치 페이지로 이어졌다.
- 한투의 VeraPort·AOS·IPInside는 설치됨, 필수 K-Defense는 미설치로 표시되었다. Chrome의 신청 화면을 인계하고 설치·본인 로그인을 요청했다. 비밀번호·인증번호를 채팅으로 요구하지 않았다.
- 이미 받은 접속 허락으로 SSH 점검을 실행했으나 `ssh: connect to host 62.171.141.206 port 22: Permission denied`였다. 추가 네트워크 권한 요청은 `network: null`을 반환했다. 다른 전송 수단으로 제한을 우회하지 않았다.

근거: 실제 DART 수집 시도 (로컬 보존 자료: `ttm-connection-attempt-20260928.json`), 저장 자료 재검사 (로컬 보존 자료: `ttm-ready-audit-20260928.json`), `work/releases/20260928-connectivity-refresh/attempt.json`.

재개 명령은 저장소 루트에서 실행한다. 기본 모드는 읽기 검사이며 `--collect`를 지정했을 때만 원천에 요청한다. 네트워크 조건이 해결되기 전 반복 실행할 이유는 없다.

## 배포 준비와 검증 범위

최종 패키지는 `work/releases/20260928-search-ttm-v27/source.tgz`이며 SHA256은 `6463c00c7b81cdbf90d2825d29411cd20858912aa8e01181cdf784c8e57e5a13`다. 641,812바이트, 155개 소스 파일이다. 패키지의 모든 파일을 현재 파일과 비교했고 runtime.env·DB·빌드 출력·로컬 UX 점검 페이지가 포함되지 않았다. 패키지 검사 (로컬 보존 자료: `../work/releases/20260928-search-ttm-v27/package-verification.json`)

기존 배포 실행기의 별도 DB 백업·복구 검사와 실패 시 이전 앱 이미지 복귀 구조를 유지했다. 이번 SSH 단계에서는 서버에 도달하지 못했으므로 새 버전 업로드·활성화·운영 재시작 결과는 없다.

- Python: 기존 회귀군과 새 검색 동시성·TTM 수집 검사 통과. 추가된 Python 검사는 7개이며 취소·오류 재시도·전체 수집 커서 보존·기간 기반 계산을 포함한다. 배포/TTM/검색 집중 재검사 16개도 통과했다.
- Node: 검색 프록시 7개 테스트 통과. gzip·쿠키 제외·동시 요청·250ms 고정 만료·LRU·실패 재시도를 검사했다.
- 변경 파일 ESLint/Ruff, TypeScript, Next production build 통과. 이전 빌드의 삭제된 경로를 참조하던 tsconfig 생성 타입 목록을 정리하고 pages 경로를 검사 대상으로 추가했다.
- 실제 웹에서 삼성전자·삼성전자우 검색과 삼성전자 상세를 확인했다. Chrome에서 실제 CSS 너비 390px일 때 내용 너비 371px로 가로 넘침이 없었다. 화면 캡처·스크롤 제스처 도구가 시간 초과되어 이번 새 스크롤 가림 검사는 완료 처리하지 않는다. 임시 viewport는 복원했다.
- 로컬 WebSocket은 두 번 연결해 snapshot·depth·epoch를 확인했다. `live_broker_receipt_verified`는 **false**다. 자료가 없는 호가를 실제 호가 수신으로 세지 않는다.
- 실제 Android·아버님 사용 평가, 실제 장중 수신, 검증된 TTM EPS와 최신 공개 배포는 미완료다.
