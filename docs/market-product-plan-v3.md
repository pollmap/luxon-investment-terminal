# 국내증시 제품 설계 v3 — 휴대폰에서 종목 하나를 제대로 보기

기준일: 2026-09-26. 이 문서는 기존 통합 설계의 우선순위와 화면 구조를 갱신합니다. 설계 목표를 구현 완료로 표현하지 않습니다.

## 1. 제품의 중심

**MTS에서 찾던 주식 정보를 휴대폰에서 쉽게 찾고, 숫자의 크기와 변화를 이해하고, 다음에도 바로 다시 보는 서비스.**

주 사용자는 1968년생 아버님입니다. 연령만으로 숙련도를 가정하지 않고 실제 사용으로 검증합니다. 로그인 없이 공개 조회하며 PC에서도 같은 기능을 제공합니다. 주문·계좌 연동은 현재 조회 중심 범위에 포함하지 않습니다.

첫 번째 완료 단위는 `종목 검색 → 가격·차트 확인 → 수급 확인 → 관심 저장 → 목록으로 복귀`입니다. 이 흐름의 읽기·조작·갱신·복구가 통과하기 전에 새 메뉴를 계속 늘리지 않습니다. 공매도와 재무 등 요청된 기능은 아래 순서대로 이어 붙이며, 기본 화면을 복잡하게 만들지 않습니다.

공개 문서와 공개 페이지에서 확인한 원리를 사용합니다. 모든 경쟁 서비스의 유료·로그인 화면이나 전체 MTS를 조사 완료한 것은 아닙니다. 경쟁사의 기능 수를 목표로 삼기보다 같은 과제의 완료율·걸린 시간·실수를 비교합니다.

## 3. 휴대폰 화면 구조

주 검수 크기는 360·390·430px입니다. PC를 축소한 표를 모바일 기본 화면으로 쓰지 않습니다.

### 시장과 관심종목

상단은 서비스 제목·검색·글자 크기 설정, 하단은 `시장 / 종목 찾기 / 관심 / 더보기` 4개입니다. 비교·내보내기·보기 설정은 해당 목록의 작업 또는 더보기로 옮기는 목표입니다. 기존 비교 화면을 삭제하지 않습니다.

시장에서는 지수와 작은 추이 차트 다음에 순위를 보여줍니다. 순위 첫 선택은 거래대금, 나란히 시가총액·상승·하락을 두고 나머지는 더보기로 제공합니다. 선택한 기준을 목록 제목·숫자와 함께 바꿉니다.

목록 한 행에는 회사 로고·이름, 현재가·등락률, **선택한 순위 기준 한 개**만 표시합니다. 별 버튼은 관심 저장, 회사명은 상세 열기로 구분합니다. 저장 뒤 취소 버튼을 제공하며 로그인 창은 띄우지 않습니다. 저장된 관심종목이 있으면 앱을 다시 열 때 관심 화면으로 시작하도록 선택할 수 있게 합니다.

업종·테마는 종목 탐색의 입구입니다. 테마 편입을 산업 분류와 혼용하지 않고, 구성 종목을 누르면 상세로 갑니다. 작은 화면에서 크기를 구분하기 어려운 히트맵을 기본 탐색으로 강제하지 않습니다.

### 종목 상세의 첫 화면

```text
← 목록           삼성전자       ☆ 관심
005930 · 코스피
현재가 크게       +등락액 · +등락률

[1일] [1주] [1개월] [1년] [전체]
가격 차트 — 누르면 날짜와 가격 고정
거래량 보조 그래프

거래대금                 시가총액

[요약] [수급] [공매도] [기업정보]
선택한 내용의 핵심 숫자 → 추이 → 상세 표
```

이는 목표 배치이며 현재 UI 전체에 적용 완료된 화면을 뜻하지 않습니다. 호가·체결은 요약 안의 `호가·체결 보기`, 증권사별 거래는 수급 안의 하위 선택, 재무·배당·주주·공시는 기업정보 안의 하위 선택으로 둡니다. 원하는 항목으로 직접 공유한 링크는 해당 항목을 열고, 사용자가 선택한 기간은 이동 중 유지합니다.

종목명과 관심 버튼은 스크롤해도 접근 가능하게 하되 고정 영역을 과하게 쌓지 않습니다. 종목 탭은 4개가 화면 폭에 들어오게 하고 숨겨진 가로 탭에 핵심 기능을 의존하지 않습니다. 가격 차트의 초기 기간은 1일, 재방문 시 그 종목에서 선택한 기간을 복원합니다.

### 공통 조작

- 본문과 숫자 기본 16px, 큰 글씨 18px, 가격 30~32px. 설명·기간도 최소 14px. 글자 확대를 전역 배율 축소로 상쇄하지 않습니다.
- 터치 대상 최소 44×44px, 자주 누르는 기간·탭·관심 버튼은 48px 목표. 아이콘만 사용하는 동작에는 접근 가능한 이름을 둡니다.
- 차트는 손가락 탭으로 날짜·값을 고정하고 이전/다음 날짜 버튼으로 정밀 이동합니다. 기본 세로 스크롤을 가로 차트 드래그가 가로채지 않게 합니다. 데스크톱 hover만으로 기능을 완성하지 않습니다.
- 기본 숫자는 만·억·조 단위를 붙입니다. 표 제목·선택 단위와 일치시키며 정확한 원값은 탭해서 확인합니다. 서로 다른 규모의 수치 비교에서는 같은 단위로 정규화합니다.
- 설명은 `?`를 누르면 하단 패널로 열리고 닫으면 같은 위치로 돌아옵니다. 긴 문장은 접고 정의·예시를 우선 표시합니다.
- 뒤로 가기는 열린 패널을 먼저 닫고 목록의 검색·필터·정렬·스크롤을 복구합니다. Android 시스템 뒤로 가기도 검증합니다.
- 확대 화면과 가로 화면을 지원하며, 상세 표에서만 가로 스크롤을 허용합니다. 화면 전체의 가로 넘침은 실패입니다.
- 다크/라이트/시스템 테마를 지원합니다. 숫자 상승·하락은 부호와 색을 함께 표시합니다. 가격 갱신 시 행 순서를 자동 변경하지 않습니다.
- 공급사명·내부 갱신시각·원천 한도는 기본 화면에 늘어놓지 않습니다. 재무 기간·잔고 기준일 등 **값의 의미가 달라지는 날짜**는 숫자와 함께 유지합니다. 연결 끊김은 짧게 표시하고 재시도할 수 있게 합니다.

## 4. MTS 정보의 가공 방식과 데이터 계약

어댑터를 많이 연결하는 것 자체가 목적은 아닙니다. 필드별 우선 원천을 정하고 정상 응답·단위·기간·거래시장 범위를 확인한 뒤 보완 원천을 사용합니다. 원천을 바꿀 때 서로 다른 날짜나 KRX/NXT 범위의 값을 한 집계로 합치지 않습니다.

| 영역 | 바로 보이는 정보 | 눌러서 보는 정보 | 가공·검증 규칙 |
|---|---|---|---|
| 가격·거래 | 현재가·등락·선택 기간 차트 | 시가/고가/저가, 거래량/대금, 호가, 체결, 52주 범위 | 실제 체결과 스냅샷 갱신 구분; 시간 역전 방지; 거래정지·신규상장 처리 |
| 투자자 수급 | 개인·외국인·기관 순매수, 선택 기간 추이 | 매수·매도, 기관 세부, 일별 표 | 주/원 전환은 양쪽 원값이 있을 때만 제공; 현재가×수량으로 실제 거래대금을 만들지 않음 |
| 외국인 보유 | 보유율과 기간별 변화 | 보유수량, 한도소진율(제공되는 경우) | 보유 비율과 당일 순매수 분리; 같은 지표의 기간 변화만 계산 |
| 증권사별 거래 | 매수·매도 상위 증권사, 각각의 수량 | 순매수 순위, 일별 추이(확보된 경우) | 매수와 매도 상위 명단의 합집합에 없는 측을 0으로 만들지 않음; 같은 집계기간·범위만 차감 |
| 공매도 거래 | 거래량, 거래대금, 거래량 비중 추이 | 일별 표, 거래대금 비중, 거래시장 구분 | 거래량 비중=공매도 거래량÷동일 범위 전체 거래량; 분모0이면 결측 |
| 공매도 순보유잔고 | 잔고수량·금액·비율, 전 보고일 대비 변화 | 장기 추이와 일별 표 | 거래량과 잔고 구분; 보고 대상 집계라는 정의를 도움말에 유지; 기준일별 정정 보존 |
| 대차·신용 | 대차잔고, 신용잔고를 각각 표시 | 대차 신규/상환, 신용 신규/상환 및 기간 추이 | 대차잔고를 공매도잔고로 대신 쓰지 않음; 확보 여부와 단위부터 검증 |
| 재무·배당 | 매출·영업이익 추이, PER/PBR/ROE, 배당 | 연결/별도, 연간/분기/TTM, 전체 재무제표·현금흐름, 배당 이력 | 실적/추정, 단독 분기/누적, 원/백만원 구분; 적자 PER은 의미에 맞게 결측 처리 |
| 기업·주주·공시 | 짧은 기업 설명, 주요 사업, 최근 공시 | 사업 구성·주주·지분변동·IR·공시 원문 | 회사와 주식종류 구분; 설명을 가격 전망으로 가공하지 않음 |
| 비교·수익률 | 같은 시작일 0%로 가격 추이 비교 | 2~4개 기업 지표, 기간별 수익률 | 공통 거래일 사용; 배당 포함 여부 명시; 수정주가 검증 전 총수익률로 표현하지 않음 |

[KRX의 공매도 안내](https://data.krx.co.kr/contents/MDC/STAT/srt/MDCSTAT300.jsp)는 거래내역과 순보유잔고를 구분하며 잔고에 보고 시차가 있음을 설명합니다. 잔고를 실시간 지표처럼 표시하지 않습니다. 공식 원천의 실제 기준일을 사용하고 고정 일수를 임의로 빼서 날짜를 만들지 않습니다.

공매도 세부 화면은 `거래 / 잔고 / 대차·신용`으로 구분합니다. 처음에는 선택 항목의 핵심 수치 2~3개와 그래프 하나만 보이고 일별 표는 펼칩니다. 빈 상태는 0건, 미제공, 아직 수집하지 않음, 조회 실패를 구분하되 사용자에게는 짧고 행동 가능한 문구로 안내합니다.

## 5. 실제 연동의 완료 기준

후보 원천은 KRX 공매도 통계, [한국투자 Open API 공식 문서·예제](https://github.com/koreainvestment/open-trading-api), 키움 REST API, OpenDART, 기존 공개 수집 어댑터입니다. 후보에 적었다고 연동 완료로 간주하지 않습니다. 공매도·신용의 실제 호출명과 응답 필드는 해당 원천 명세 및 샘플 응답을 확인한 뒤 고정합니다.

신규 영역마다 다음 순서로 완료합니다.

1. 최소 3개 종목의 원문 응답과 날짜·단위·범위 확보. 보통주/우선주, KOSPI/KOSDAQ, 거래 없는 날과 결측 예제를 포함합니다.
2. 원문 보존 → 정규화 → 결정론적 계산 → API → 모바일 핵심 화면 → 펼친 표를 한 흐름으로 연결합니다.
3. 원값과 표·차트·기간 합계를 대조합니다. 수량과 금액, 비율과 증감률, 잔고와 거래량의 혼동을 테스트합니다.
4. 목록에 없는 종목을 조회해도 수집 작업이 등록되고 완료/실패 상태가 복구되는지 확인합니다. 전 종목 등록률과 항목별 채움률은 운영 보고에서 분리합니다.
5. 실제 배포 주소에서 확인한 뒤 공개 연결 완료로 기록합니다.

실시간 완료는 브로커 인증 성공, 장중 실제 메시지 수신, 종목별 구독 해제, 끊김 뒤 스냅샷 복구, 중복·역전 메시지 방지, 복수 사용자 구독 공유까지 확인한 상태입니다. 공개 시세 주기 수집이나 웹소켓 전송만으로 이를 대체하지 않습니다.

## 6. 개발 순서 — 한 단계의 핵심 흐름을 끝낸 뒤 확장

| 순서 | 완료 단위 | 통과해야 다음 단계로 이동 |
|---|---|---|
| 1 | 모바일 검색 → 가격/차트 → 관심 저장 → 복귀 | 실제 기기에서 가독성·터치·큰 글씨·뒤로 가기, 끊김/재접속, 새로고침 후 저장 복원 |
| 2 | 수급·외국인 보유·증권사별 거래 | 주/금액/비율 구분, 기간 선택과 그래프·표 일치, 상위 거래원 누락 처리 |
| 3 | 공매도 거래·순보유잔고 | 실제 원천 연결, 보고일 처리, 결측·정정 사례, 모바일 도움말과 추이 |
| 4 | 대차·신용, 재무·배당·주주 깊이 보강 | 전 종목/전 기간별 실제 데이터 감사; 자료 없는 항목의 복구 동선 |
| 5 | 비교·스크리너·저장 보기·내보내기 확장 | 기본 화면을 늘리지 않고 원하는 조건 저장·재사용; 모바일 2종목 비교 가독성 |

호가·체결 스트리밍은 인증이 가능해지는 즉시 1단계의 가격 화면에 연결합니다. 외부 인증이 막힌 동안 모바일 화면·수급 등 독립적인 작업을 계속합니다. API 장애 하나가 전체 화면을 막지 않게 영역별 실패를 분리합니다.

## 7. 속도·운영·자동화

- 종목명·가격·관심 조작을 먼저 렌더링하고 무거운 재무·공시·심화 차트는 선택 후 불러옵니다. 로딩 중에도 뒤로 가기와 검색은 동작해야 합니다.
- 시세, 과거 차트, 공시/재무는 별도 큐와 캐시를 사용합니다. 많은 재무 요청 때문에 신규 종목 차트가 밀리지 않게 합니다.
- 현재 화면과 보이는 관심종목에 갱신 우선순위를 줍니다. 앱이 숨겨지면 폴링을 쉬고 복귀 시 보정합니다. 전 종목 수집은 저장된 커서로 재시작합니다.
- 요청 취소, 중복 요청 묶기, 제한 있는 캐시, 백오프, 디스크 여유 감시를 둡니다. 실패 시 마지막 정상 자료를 보존합니다.
- 성능 목표는 모바일 p75 LCP 2.5초 이하·INP 200ms 이하·CLS 0.1 이하, 캐시 검색 API p95 300ms·상세 API p95 500ms입니다. 목표이며 달성 측정값이 아닙니다. 실제 외부 네트워크·기기 측정과 서버 내부 측정을 분리합니다.
- 자동 검사는 핵심 동선, 360/390/430/768/1440px, 큰 글씨·다크모드, 데이터 계약, 재접속을 배포 전 수행합니다. 배포 뒤 health뿐 아니라 검색 결과·종목 가격·차트·수급 행을 확인합니다.
- 수집 자동화와 제품 개선 자동화는 분리합니다. 자료는 주기 수집하고, UX는 실제 오류·사용 과제 결과에 따라 수정합니다. 경쟁 서비스 변경을 이유로 검증 없이 화면을 자동 교체하지 않습니다.

## 8. 아버님 사용성 검수

설명 없이 아래 과제를 수행하게 하고 막힌 위치와 눌렀던 버튼을 기록합니다. 자동 브라우저 테스트를 실제 아버님의 사용성 검수로 대신하지 않습니다.

1. 삼성전자를 찾아 오늘 올랐는지 확인한다.
2. 차트를 1개월로 바꾸고 원하는 날의 가격을 읽는다.
3. 외국인이 선택 기간에 순매수했는지 확인하고 보유율과 구분한다.
4. 어느 증권사에서 매수량이 많았는지 찾는다.
5. 공매도 거래량과 잔고가 어떤 날짜의 숫자인지 확인한다.
6. 관심종목에 넣고 닫았다 다시 열어 찾는다.
7. 직전 순위 목록으로 돌아와 읽던 종목을 찾는다.

1·2·6·7은 도움 없이 모두 성공해야 1단계 통과입니다. 3~5는 각 기능 출시 전 별도로 통과해야 합니다. 5명 평가에서는 각 과제 4명 이상 성공을 초기 기준으로 하되, 아버님이 실패한 핵심 과제는 평균으로 가리지 않습니다. 기기·브라우저·글자 설정과 성공시간·오탭·도움 횟수를 함께 기록합니다.
