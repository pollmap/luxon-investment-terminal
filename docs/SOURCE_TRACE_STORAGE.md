# 시계열 출처 공유 저장 계약

2026-10-09. 신규 저장 증가를 줄이는 변경이며 기존 자료 정리·삭제·대량 마이그레이션은 포함하지 않습니다.

## 확인한 중복

22:34 KST 운영 DB의 삼성전자 시계열 4개에서 최신 100행씩만 읽었습니다. 수정 일봉·원주가 일봉·대차는 출처 JSON이 행 JSON 크기의 85.66%·85.76%·88.18%였고, 고유 출처는 각각 2·2·3개였습니다. 투자자 수급 표본의 최상위 출처 비중은 3.11%로 달랐습니다. 이 비율을 전체 DB의 회수 가능 용량으로 환산하지 않습니다.

당시 테이블과 인덱스 합계는 시계열 26,801,750,016바이트, 재무 사실 12,839,550,976바이트였습니다. 근거는 `work/source-trace-dedup-20261009/baseline.json`입니다. 재무 사실 저장은 이번 변경 범위가 아닙니다.

## 저장과 조회

- `market_source_traces(digest, byte_count, payload)`를 추가합니다. 기존 테이블의 구조와 행은 변경하지 않습니다.
- 출처 dict를 `ensure_ascii=False`, 정렬된 키, 공백 없는 JSON, `allow_nan=False`로 직렬화한 UTF-8 전체 바이트에 SHA-256을 적용합니다.
- 수집 시각, 공시 시각, 문서 해시, 정정 참조, `null`, 중첩 배열·객체 등 모든 필드를 보존합니다. 이 해시는 **출처 JSON 자체**의 해시이며, 원문 파일의 해시를 대체하지 않습니다.
- 새 시계열 행은 `{"_market_storage":"source-trace-sha256-v1","row":...}` 봉투를 사용합니다. 내부 `source_trace` dict는 `{"$market_source_trace":"<sha256>"}`로 참조합니다.
- 전체 행이 작아지는 경우에만 봉투를 사용합니다. 짧은 출처와 결측은 기존 inline JSON으로 남길 수 있습니다.
- 기존 inline 행과 새 봉투를 함께 읽습니다. API·계산에 반환하기 전에 원래 출처 dict를 복원하며 저장용 참조는 외부 응답에 노출하지 않습니다.
- 같은 조회 안에서 출처를 묶어 읽습니다. 한 IN 조회는 400개 이하이고, 각 행의 출처는 독립된 dict로 반환합니다.
- 저장 바이트 수·해시·정규 JSON을 검증합니다. 참조 누락·변조·알 수 없는 형식은 명시적 무결성 오류이며 빈 출처나 0으로 대체하지 않습니다.
- 참조 충돌 시 기존 출처를 덮어쓰지 않습니다. 새 행·출처·수집 커서는 같은 트랜잭션에 들어갑니다.
- 경제적 값이 같으면 기존 digest 규칙을 그대로 적용해 행을 다시 쓰지 않습니다. 읽기와 동일 자료 재수집으로 기존 inline 행을 일괄 전환하지 않습니다.
- 정정으로 행 값이 바뀌면 새 출처를 연결하되 이전 공유 출처를 삭제하지 않습니다. 원문 보관과 기존 정정 체계도 유지합니다.

## 2단계 배포

1. **읽기 호환 버전부터 배포합니다.** `MARKET_SHARED_SOURCE_TRACES` 미설정 또는 `0`이 기본이며 새 참조를 쓰지 않습니다. API와 모든 수집 프로세스에서 새 봉투를 읽을 수 있는지 확인합니다.
2. **쓰기 활성화는 별도 배포입니다.** 읽기 호환 버전을 이전 정상 버전으로 확보한 뒤 `MARKET_SHARED_SOURCE_TRACES=1`을 설정합니다. 신규/정정 행부터 적용됩니다.

참조 행을 한 번이라도 저장한 뒤에는 이 환경변수를 다시 `0`으로 바꿔도 기존 참조가 사라지지 않습니다. 따라서 **참조를 읽지 못하는 v96 이하로 앱을 되돌리면 안 됩니다.** 배포 도구는 읽기 호환 버전을 롤백 하한으로 강제해야 합니다. 이 저장 모듈 자체가 배포 도구의 롤백 허용 여부를 바꾸지는 않습니다.

백업은 `market_source_traces`와 이를 참조하는 행을 동일 DB 스냅샷에 포함해야 합니다. 전체 DB 덤프는 이 테이블을 포함하지만, 선택적 복사·복원 도구에는 새 테이블을 누락하지 않았는지 별도로 검사해야 합니다. 원본 파일을 백업했다는 사실만으로 출처 테이블 복원이 보장되지는 않습니다.

첫 실행의 새 테이블 생성은 기존 `TimeSeries` 스키마 초기화와 같은 방식의 추가 DDL입니다. 운영 DB에 이 테이블을 만들거나 참조 저장을 켜는 동작은 별도 배포 작업으로 수행합니다.

## 검증 범위

회귀 검사는 기본 off, 읽기 호환, 한글·중첩·null·정확한 문자열·수집 시각 보존, 중복 재수집, 정정, 트랜잭션 롤백, 해시 변조, 참조 누락, 1,100개 출처의 SQLite 변수 한도, 조회별 dict 독립성, 작은 행의 inline 유지와 신규 저장 크기를 확인합니다.

Toss·수급·과거 자료 회귀 검사를 참조 저장 활성화 상태에서도 실행합니다. 모의자료 테스트와 운영 데이터의 실제 참조 저장·복원 검증은 구분합니다. 이 작업은 이미 저장된 26.8GB를 줄였다는 의미가 아닙니다.
